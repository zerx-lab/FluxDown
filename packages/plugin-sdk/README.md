# fluxdown-plugin-sdk

TypeScript types, a JSX runtime for portable views, the manifest validator and a CLI for building [FluxDown](https://fluxdown.com) plugins.

## Quick start

```bash
npx fluxdown-plugin-sdk create my-plugin --identity me@my-plugin --name "My Plugin"
cd my-plugin
npm install        # or: bun install
npm run pack       # → me@my-plugin-0.1.0.fxplug
```

The template has one activity-bar view (a JSX counter) and one command.

To try it in FluxDown: **Settings → Extensions → Plugins → From a directory**, pick the project's `dist/` folder (dev mode), approve the permissions dialog, then run `npm run dev` so every save rebuilds `dist/`. After changing `manifest.json`, press **Reload** on the plugin row.

## CLI

| Command | |
|---|---|
| `fluxdown-plugin create <dir> [--identity a@b] [--name "Name"] [--sdk <path>]` | Scaffold a project. |
| `fluxdown-plugin build [dir]` | Bundle entries into `dist/`, copy manifest and assets, validate. |
| `fluxdown-plugin validate [dir]` | Validate `dist/` with the engine rules. |
| `fluxdown-plugin pack [dir]` | Build, then zip `dist/` into `<identity>-<version>.fxplug`. |
| `fluxdown-plugin dev [dir]` | Watch and rebuild. |

Configuration lives in `fluxdown-plugin.config.json`:

```json
{
  "entries": { "main.js": "src/main.tsx", "resolve.js": "src/resolve.ts" },
  "desktop": { "ui/dashboard.js": "src/desktop/dashboard.ts" },
  "assets": ["rules.json"]
}
```

`entries` are bundled as classic ES2022 IIFE scripts (no `import`/`export` survive); `desktop` entries stay ES modules with the desktop host modules external; `assets` are copied verbatim.

## Package exports

| Import | Contents |
|---|---|
| `fluxdown-plugin-sdk` | Types (`flux`, view nodes, entry contexts, theme tokens) and the manifest API. |
| `fluxdown-plugin-sdk/manifest` | Zero-dependency `validatePackage` (every install check: manifest, limits, sniff pack, view icons, page scripts and archive entries), `reviewOf`, `validateManifest`, `riskOf`, `networkHostsOf`, `VALID_PERMISSIONS`. The plugin index admits packages with the published copy of this file. |
| `fluxdown-plugin-sdk/runtime` | `defineResolver`, `defineHooks`, `defineInterceptors`, `defineAuth`, `defineSubscription`, `defineArchive`, `defineMain`. `defineInterceptors({ prepare, refresh, probed, selectVariant, selectPeriod, segments, liveSegments, finalize, failed })` installs the single `intercept(ctx)` entry (requires the `intercept` permission and a manifest `interceptors` block). `defineArchive((ctx: ArchiveContext) => ({ folderName }) \| null \| undefined)` installs `globalThis.archive` (sync or async; manifest `contributes.archive` plus the `archive` permission); the archive script only has `flux.settings`, `flux.logger` and `console`. |
| `fluxdown-plugin-sdk/ui/jsx-runtime` | JSX runtime; set `"jsxImportSource": "fluxdown-plugin-sdk/ui"`. |
| `fluxdown-plugin-sdk/types/desktop` | Declarations for desktop UI scripts (generated by the desktop runtime). |

Full documentation: [SDK & CLI](https://fluxdown.com/docs/en/plugins/sdk/), [Views](https://fluxdown.com/docs/en/plugins/views/), [Permissions](https://fluxdown.com/docs/en/plugins/permissions/).

## Working on the SDK

```bash
bun install
bun run gen          # regenerate src/types/view.d.ts and theme.d.ts
bun run gen:check    # fail if the generated files are stale
bun run typecheck
bun test             # includes the shared manifest fixtures used by the Rust engine
bun run build
```

The plugin index vendors `dist/manifest.mjs` from the **published** npm package (its `sync-validator` workflow picks up each release), so a rule change reaches the index by releasing the SDK (`plugin-sdk-v*` tag).

`src/types/view.d.ts` is generated from `native/protocol/src/plugin_view_schema.json`, `src/types/theme.d.ts` from `website-v2/src/lib/gpui-theme/registry.json`, and `types/desktop.d.ts` by the `gen_plugin_typings` example in `crates/plugin_ui`. The manifest tests read `native/engine/src/plugin/fixtures/manifest_cases.json`, the same file the Rust tests use.
