有些 BitTorrent 对端(俗称"吸血"客户端)会反复从你这里下载同样的数据,或谎报进度让你不停上传。**BT 防吸血**是 FluxDown 内置的防护:它观察每个对端的行为,记录规则"本应执行"的动作,并且只对你打开"执行"的规则真正限速、停止上传或封禁对端。

## 默认行为

开箱即用时 FluxDown 刻意保守:

- 防护总开关**开启**,但所有检测规则与云名单默认都是**仅观察**:命中只写入事件日志,不会限速或封禁。查看日志后,再把你信任的规则切到**执行**。
- **私有种子默认跳过**(不检测、也永不上报)。
- **局域网对端永远豁免**:私网、回环、链路本地、运营商级 NAT(100.64.0.0/10)与 IPv6 ULA 地址。
- **仍在下载中的任务**最强动作为**限速**(可配置),避免误判拖慢你自己的下载。

## 架构

![BT 防吸血架构:对端、librqbit 钩子、引擎 bt_guard、daemon RPC、agent、客户端与 FluxCloud](/docs/bt-guard/architecture.svg)

对端连接到 FluxDown 定制的 librqbit,后者在接纳连接、上报协议事件与调度上传处调用钩子;引擎的 `bt_guard` 模块判定并回复放行 / 限速 / 拒绝上传 / 断开。结果经 daemon 传给 agent,agent 还负责拉取并验签云名单、(在你同意后)上报证据,以及提供 REST 接口。四端客户端看到的是同一份状态。

## 检测规则

每条规则有三种模式:**关闭**、**仅观察**、**执行**。对端以 *IP 组* 识别:IPv4 为单个地址,IPv6 按前缀(默认 `/64`,可在 `/48` 到 `/128` 调整)。

| 规则 | 强度 | 检测内容 | 默认 |
|---|---|---|---|
| 超量下载 | 强 | 某个对端组从你这里下载的数据超过种子大小的 200%(且至少 64 MiB——更小的种子不触发)。 | 仅观察 |
| 重复请求 | 强 | 对端请求自己已声明拥有的分片,且涉及至少两个不同分片。 | 仅观察 |
| 进度回退 | 强 | 对端重连后上报的分片明显变少(丢失超过 7%),以便重新下载同样的数据。 | 仅观察 |
| 汇报滞后(探测) | 中 | 你已送达(并过了 120 秒宽限)的分片中,超过一半始终没出现在对端进度里。FluxDown 会先断开它一次作为探测:重连后仍缺失记为进度回退,补齐则清除嫌疑。同一组 24 小时内最多探测一次。 | 仅观察 |
| 客户端特征 | 弱 | 客户端名或 peer ID 命中云名单里已知的吸血客户端。单独出现绝不封禁。 | 仅观察 |
| 云名单 | 按条目 | 对端地址在签名云名单中,由条目决定封禁、拒绝上传或限速。 | 仅观察 |

## 处置阶梯

只有"执行"模式的规则才会真正处置;"仅观察"只记录本应执行的动作。

| 信号 | 动作 |
|---|---|
| 强 | 记一次违规,随后**封禁**:首次 24 小时,每再犯一次 ×4(24 小时 → 4 天 → 16 天 …),最长 30 天。30 天内无新违规则清零。 |
| 中或弱 | 做种任务:**拒绝上传**(choke);下载中任务:**限速**(共享上传上限,默认 32 KiB/s)。单独出现绝不封禁。 |
| 云名单条目 | 按条目自带动作:封禁至条目过期,或拒绝上传 / 限速。 |

封禁会拒绝该组的新连接,并在所有种子上断开它。首次封禁时长、最长时长、限速速度、上述阈值与"下载中动作上限"都可配置(见[设置](/docs/zh/getting-started/settings/))。

## 名单分层

条目分五层,多层同时命中时优先级高者生效:

1. **白名单**——始终放行(优先级最高)。
2. **手动**——你自己添加的条目。
3. **自动**——上述规则产生的封禁。
4. **云名单**——签名云名单。
5. **过滤文件**——你订阅的纯文本 IP 列表(每行一个地址或 CIDR,PeerGuardian 文本格式亦可),每 24 小时刷新。

云名单与过滤文件里宽于 IPv4 `/16`、IPv6 `/32` 的条目会被丢弃,坏名单无法封掉整片区域。云名单条目不能在本地删除——请改为把该地址加入白名单。

## 云名单

在 BT 引擎运行期间,FluxDown 约每 6 小时拉取一份由 FluxCloud 签名的名单(仅当"使用云名单"开启时),使用前在本地用 **ed25519 验签**。来源:

- **BTN-Collected-Rules**(PBH-BTN 维护),许可证 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)——<https://github.com/PBH-BTN/BTN-Collected-Rules>,由 FluxCloud 镜像并重新签名。
- **FluxCloud 共识名单**——由多名合格用户各自独立上报、并经管理员批准后才发布的对端。

客户端会防范错误或被劫持的名单:签名无效、版本号回退、已过期、覆盖知名公共地址(内置金丝雀 IP),或与上一版相比变化超过 50%(上一版 ≥ 1000 条时),整份文档会被拒收。拒收时保留上一份并在云名单区块显示原因;名单过期后云名单层暂停("已过期"),直到拿到新名单。

## 证据上报(可选)

你可以上报触发规则的对端,帮助构建共识名单。该功能**默认关闭**、仅保存在本机,需要已登录 FluxDown 账号并在弹窗中明确同意。

- **会发送:**违规对端的 IP 组、命中的规则、字节数与比例、客户端名或 peer ID 前缀,以及种子大小与 infohash。
- **绝不发送:**文件名、路径、种子名,以及**私有种子**的任何内容。
- FluxCloud 收到后立即用服务端密钥对 infohash 做 HMAC,不保存原值。

完整说明见[隐私政策](/zh/privacy/#bt-guard)。

## 在哪里使用

- **桌面端与 Web:**在*设置 → BitTorrent*中有三个标签页——**防吸血**(规则、阈值、动作、豁免、云名单、过滤订阅、证据上报、今日统计)、**封禁名单**(浏览、搜索、添加、解封、加白、导出)与**事件日志**。BT 详情的*连接*页新增 **IP 组**、**已上传到该组**、**嫌疑**、**规则**、**动作**列;右键菜单可对该对端组临时封禁 1 小时 / 1 天 / 7 天或永久封禁、限速一天、加入白名单,或查看证据。
- **Android:***设置 → BitTorrent*中提供防吸血设置、封禁名单(支持手动添加与导出)与事件日志(可按类型 / 规则筛选、分页、查看详情)。
- **iOS:***设置 → BitTorrent*中提供防吸血设置与封禁名单(浏览、解封、加白);没有事件日志、手动添加与导出。
- 逐连接的列与右键操作为桌面 / Web 功能。

## REST 接口

开启管理 API 后(见 [API 概览](/docs/zh/api/overview/))可用以下路由,完整结构见 `/api/v1/openapi.json` 提供的 OpenAPI 文档。

| 路由 | 作用 |
|---|---|
| `GET /api/v1/bt/guard/state` | 总开关、会话状态、今日统计、云名单状态、订阅状态与各层条目数。 |
| `GET /api/v1/bt/guard/entries` | 列出条目。参数:`layer`、`rule`、`query`、`containsIp`(只返回 CIDR 覆盖该 IP 的条目,含云名单的宽网段)、`offset`、`limit`(1–500)。 |
| `POST /api/v1/bt/guard/entries` | 添加手动或白名单条目。 |
| `DELETE /api/v1/bt/guard/entries/{id}` | 移除条目(解封)。云名单层条目返回 400。 |
| `GET /api/v1/bt/guard/events` | 事件日志。参数:`rule`、`kind`、`ipGroup`(某个 IP 或 `2001:db8::/64` 这样的组)、`offset`、`limit`。 |

## 被误封怎么办

其他 FluxDown 用户可能通过云名单封禁了你的地址。请在你实际使用的网络下打开 [BT 防吸血自查页](/zh/bt-guard/):它会显示你当前 IP 是否在名单中、原因与到期时间,并可提交申诉。申诉通过后条目会被移除并加入白名单。自查页只回答访问来源的地址,不支持查询任意 IP。

## 附带的兼容性修复

集成的 BT 引擎还包含两项与规则无关的通用修复:

- FluxDown **始终发送 HAVE 消息**。此前抑制"冗余" HAVE 会让 PeerBanHelper 等进度检测工具误以为对端在吸血而把你封禁。
- 对端**已取消**的上传请求会在读盘之前被丢弃。
