## GPUI PC 客户端（`crates/`，三进程本机链路）

**桌面发行物为 GPUI**：Windows / macOS / Linux 发布 `fluxdown-desktop → fluxdown-agent → fluxdownd`，浏览器中继为 `fluxdown_nmh`（`.github/workflows/release.yml` 与 `scripts/package_gpui_{linux,macos}.sh`）。移动端为 `mobile/Android` 与 `mobile/FluxDown`，经 `native/mobile` 的 UniFFI 连接 Rust 核心。GPUI 关于页与服务版本取 `fluxdown_protocol::APP_VERSION`：正式构建由 tag 注入 `FLUXDOWN_APP_VERSION`，本地回退 crate 版本，见 `ops.md`「发布与 CI」。

GPUI 关于页与新版本提醒窗口的更新说明（`crates/settings/src/sections/about.rs::release_notes`）按界面语言（`Translator::locale`）筛选 release body 的 `fluxdown:lang:zh/en` 区块：中文界面显示中文，其余显示英文；缺少目标翻译时显示已有语言，无标记的历史说明保留原文。每个版本的标题统一为「v版本 + 发布日期」（`published_at` 的日期部分），正文开头与之重复的版本标题（`## 0.5.7 - …`、`## [0.5.6] - …`、`## v0.4.8 - …`）由 `strip_version_heading` 去掉；正文行高为字号 1.6 倍，版本之间以细线分隔。Web（`web/src/lib/releaseNotes.ts`）与原生 Android（`UpdateView.kt`）同规，见 AGENTS.md「镜像契约」。

GPUI 下载设置的 User-Agent 在 `sections/user_agent.rs` 自渲染整行：标题/说明与预设下拉优先同行，按卡片实际可用宽度 flex-wrap，空间不足时下拉移到下一行；仅自定义模式在下方显示占满卡片宽度的输入框。复用设置页字号、间距和控件宽度档位，保留标题/说明搜索元数据；不按窗口单双列写死断点，也不把长输入塞进右侧控件列。

GPUI 与 Web 的下载设置「线程数量 / 最大 CDN 节点数」采用「自动 / 自定义」下拉，仅自定义显示正整数输入；底层仍以 0 表示自动，不新增配置键。切回自动再选自定义时恢复当前会话记住的数量，首次自定义为线程 16 / CDN 节点 2，范围取协议目录；线程自动模式下单独显示自动模式线程上限，手动高线程数仍显示风险提示。两项不是乘法关系：CDN 数量约束节点 IP，线程数量约束单任务并发。

依赖方向固定为 `i18n` / `theme` / `icon_pack` → `components` → `shell` / capability crates → `app`。`app` 只做窗口与单一 agent 会话装配；capability 之间不互相依赖。

- `i18n`：`build.rs` 自动嵌入共享 `assets/i18n/*.json`；locale 规范化、英文键级回退、空值回退和插值契约跨端一致。繁体中文（台湾）资源为 `zh-TW.json`：GPUI/Web 内部代码 `zh-tw`，iOS 保留文件名大小写，扩展代码 `zh-TW`。中文显式 `Hans`/`Hant` 优先地区，无显式文字时 TW/HK/MO 使用繁中；GPUI 基础组件经 `settings::component_locale` 映射为 `zh-TW`（其余语言的组件内置文案用 en）。非基线语言由 ZerxLabBot 翻译自动化维护（滚动 PR `bot/i18n-sync`，术语表 `i18n/glossary/<locale>.md`，来源哈希 `i18n/source-lock.json`，见 `rule://i18n-baseline-zh-en`）；GPUI / Web / Android / iOS 均自动发现新语言文件，只有 iOS 系统语言声明（`Info.plist` / `knownRegions`）需手动补。
- `theme` / `components`：主题 v2（`crates/theme`）。**文件格式 `ThemeDocument` 与运行时解耦**：wire 只含字符串/数字，camelCase，全字段可选、未知键原样保留，`schemaVersion`=2（更高版本 best-effort 加载 + 诊断；v1 内部格式与 Flutter FluxThemeJson 自动迁移/适配），单字段非法只回退并记 `Diagnostic`，绝不整体失败。解析顺序 `<mode>` 层 > `tokens` 共享层 > `extends` 内置基底 > 注册表默认表达式（`Ref`/`RefAlpha`/`Mix`/`Literal`/`Contrast`——保持色相只调亮度直到 WCAG 对比度达标，Rust `extended.rs::with_min_contrast` ↔ TS `value.ts::withMinContrast` 逐步 f32 镜像），越界 clamp、循环引用回退。**唯一事实源 = `registry.rs::TOKENS`**（颜色/圆角/间距/排版/阴影 + 扩展色、状态色、进度色、`stroke`、`focusRing`、`icon`、`density.*` 高度、`components.*` 组件圆角）；`kitBound` token（input/dialog/menu/tooltip 圆角）只跟随 `radius.md/lg`（gpui-component 限制）。运行时 `FluxThemeState::{tokens,extended,density,components}()`，业务 crate 禁写形状/高度/边框字面量，一律读 token；强调色、亮色主色对比度（`ensure_primary_contrast`）、ui_scale 仅运行时生效。正文基线 `typography.sm` = 13/18。新增/改名 token：只加不改，改名走 `migrate.rs` 声明式 rename，重跑 `cargo run -p fluxdown_ui_theme --example gen_theme_registry`（产出 `website-v2/src/lib/gpui-theme/registry.json`、`website-v2/public/schemas/gpui-theme.v2.json`、`crates/theme/tests/fixtures/*.resolved.json`，测试守卫漂移）；已发布版本的 fixtures 永久保留。theme 同时把 DataTable 投影为无网格、面板分隔把手投影为 hairline。
- 内置主题预设（`builtin.rs`）：多数只有调色板（`Palette` → Base token）；`preset_overrides` 让预设额外固定非 Base token（形状 / 密度 / 阴影 / 扩展色），经 `base_values` → registry `builtins` 导出，Rust `eval_default` 与 TS `resolve.ts::evalDefault` 都「基底值优先于默认表达式」，文件层仍最优先。预设固定值禁含 `ACCENT_TOKEN_PATHS` 与 `kitBound` token（单测守卫）。`graphite` / `graphite-light`（石墨 / 石墨亮色）= 三层中性色 + 信号蓝、2/4px 方角、1px 焦点、控件 / 导航行 32，亮暗共用 `graphite_overrides`；旧版零视觉差测试只覆盖纯调色板预设。新增预设同改 `appearance.rs`（`BuiltinThemeId`）、`builtin.rs`、`document.rs::builtin_name`、Web `appearance.ts`、官网 `themeBuilder.ts` 与 contributing 文档保留名、共享 i18n `theme<Name>`。
- 主题库：设置「外观」导入（多选 JSON，诊断汇总通知）/导出（仅差异 / 完整）/删除。**唯一事实源 = agent 偏好** `appearance.custom_themes.<编码 id>`（值为主题文件原文，`fluxdown_protocol::custom_theme_key`：规范 id `[a-z0-9_]` 段以 `-` 相连、≤64 字节，`-` 编码为 `.`；原文转义后 ≤64 KB = 云端单值上限），逐主题随配置同步（「外观」分组含集合范围键 `appearance.custom_themes`，本机专属按范围键作用于全部主题）。`settings::theme_library`：导入 = 解析 + 按 `meta.id` 清洗分配 id（冲突加 `-N`）+ `set_pref`；删除 = 写 `null` 墓碑；注册 / 注销只由 app `apply_preferences` → `sync_theme_library`（先于外观投影，原文不变不重解析）完成，云端增删改与本机操作同一路径。旧版 `<data_root>/themes/<id>.json` 由 app `legacy_themes.rs` 在首个快照后一次性迁入偏好，agent 确认后删文件（同 id 原文冲突 / 超限的保留）。偏好 `appearance.{dark,light}_theme` 取 `builtin:<id>` 或 `custom:<id>`（缺失 id 回退该槽位内置默认）。
- 图标：`components::FluxIcon`（Lucide 1.48.0 子集，ISC，线宽 1.75，实现 `IconNamed`，资源由 `ComponentAssets` 提供、app 组合进 `DesktopAssets`）；gpui-component 自带 ~99 个图标语义不全，文件类型 / 任务状态 / 新增图标一律走 FluxIcon（新增：下载 SVG 到 `crates/components/assets/icons/` 并登记 `flux_icons!` 表）。`components::category_icon` 是分类图标唯一映射（侧栏与设置分类编辑器共用）；会刷新的数字统一 `font_features(tabular_numbers())`（界面字体数字为比例宽）。
- 字体：GPUI 用系统默认界面字体，不内嵌字体文件——内置主题 `typography.sans` 为哨兵 `system-ui`（`theme::SANS_FONT_SENTINEL`），运行时换成 gpui 的 `.SystemUIFont`（macOS 系统字体、Windows 系统界面字体如微软雅黑 UI / Segoe UI）。Windows 汉字按界面语言处理（`theme::cjk`）：中文界面且主题 / 用户未指定字体时主字体换成雅黑 UI（简）/ 正黑体 UI（繁），所有窗口根节点经 Root 插件挂「偏好字形在前」的汉字回退链（非中文界面按系统语言定顺序），避免 DirectWrite 按系统区域回退到明体（#1003）；macOS / Linux 不变。共享 `assets/fonts/MiSans-*` 仍供 Web SPA 使用；它是约 7.7k 字形的子集（缺繁体、`·` 等），曾导致 Windows 上缺字逐字回退雅黑、同一行大小粗细不一，GPUI 不得再引入。桌面字体选择框创建时自动读取本机字体，无手动读取按钮；`Select` 用 `Size::Large` 取得 1rem 字号（选择框、搜索框、列表一致），高度独立设为 `density.control` 并清零纵向内边距，禁止把高度像素传给 `with_size`（会同时放大字号）。
- 字体大小：设备本地偏好 `desktop.font_size`（整数 px 正文字号，界面缩放前，10~24；缺失/`null` 跟随主题；不进同步目录，Web 不镜像——浏览器自带缩放）。倍率 = 所选字号 / 主题 `typography.sm.size`，与 `ui_scale` 相乘。`theme::fonts::fit_text` 在安装主题时按倍率缩放全部排版角色，再把行高抬到不小于「界面/等宽字体自然行高（ascent+|descent|）× 字号」，并把承载文字的 `density.{control,navRow,statusBar,statusControl,sectionHeader,taskRow,taskRowCompact}` 按行高增量加高（只增不减；`toolbarButton`/`titleBar`/图标/间距/圆角不变）。业务代码规则：含文字的高度一律由排版 / 密度 token 推导（不写 `px` 常量）、`text_size` 必须配同角色 `line_height`；装文字的定宽（标签列、定格式数字列）用 `FluxThemeState::text_extent(base)`；虚拟列表行高须随主题刷新，不得构造时缓存。
- 控件套件（`components/src/kit.rs`，所有窗口必须用）：控件高度取 `density.control`（默认 28）：带文字按钮 / 输入框 / 下拉（outline + `dropdown_caret`）/ 数字输入一律 `.control(cx)`（`Input` 的高度必须走 `Styled::h`——它自带的同名 `h()` 只作用于多行，单行会静默退回 26px；gpui-component 按钮字号由 `Size` 写在内部 label 上，故套件用 `Size::Medium`，业务禁止 `.small()/.xsmall()`/自定义高度）；纯图标按钮 `.control_icon(cx)`，chrome 区用 `toolbar_action_button`；标签页一律 `segmented_tabs`（不用 `TabBar`/自造按钮组）；复选框一律 `check_mark`/`check_row`（不用 gpui-component `Checkbox`）；对话框标题 `dialog_title`、底栏 `dialog_footer(cancel, ok, DialogIntent, cx)`（取代 `DialogButtonProps`，其默认按钮 32 高且默认不显示取消）；卡片 `card`（surface + hairline + `components.card.radius`，无阴影）。theme 把 gpui-component `background` 投影为 `surface`（对话框/输入框白底）。
- 强调色落点：选中导航（侧栏/设置/活动栏/RSS）只给图标上强调色 `colors.navSelectedIcon`（≥3:1，统一经 `components::nav_icon_color`），文字 `navSelectedForeground`、底色仍中性 `navSelected`；下载中有任务时状态图标同色；链接 / 限速生效 / `ButtonVariant::Link` 用 `colors.accentText`（与 surface ≥4.5:1）；光标 `caret`、选区 `textSelection`、拖放 `dragBorder`/`dropTarget` 均为 token。gpui-component 派生色（caret/selection/link/list_active/progress_bar/slider/drag/drop/table…）在 `theme/manager.rs::project_onto_kit` 统一重写（`ComponentTheme::change` 按库默认 neutral primary 推导，不重写就停在黑/灰）；新增库控件读到的派生色必须补进这里。悬停与大面积底色永不上强调色。
- `shell`：只拥有窗口 chrome、路由与内容槽，不知道下载、设置、账户、RSS 或扩展。主窗口统一顶栏高 `density.titleBar`（默认 40，不随 ui_scale 缩放，交通灯按它垂直居中；Windows/Linux 为 logo + `AppMenuBar` + 自带窗口按钮），`ShellRoute::with_title_bar(view)` 让活跃路由往顶栏挂插槽；插槽内可交互元素必须拦截左键 `mouse_down` 冒泡，空白处保持拖拽/双击。活动栏、侧栏、顶栏、状态栏同为 `chrome` 底，内容区 `surface`。
- 下载页布局：顶栏插槽 `components/title_bar.rs::DownloadTitleBar`（左：主按钮新建，左缘与内容区（侧栏右侧）对齐——`DownloadView.content_left` 与插槽自身左缘均由 `title_bar::left_edge_probe`（`absolute().inset_0()` canvas）在 prepaint 测得，差值作可收缩的前导留白，前导区更宽时贴插槽左缘；右：搜索、「视图」弹层：列/分组/排序/密度/详情面板）；批量操作只在选中 ≥1 时以内容区底部浮动选择条出现（`selection_bar.rs`，依赖 `SelectionSummary{count,any,any_local,any_active,any_resumable}`）；状态栏只放全局速度、全部暂停/开始、限速、代理快速切换、完成后关机、剩余空间。任务表：文件名列按容器宽回算吸收剩余宽度（不可手动拖宽）；表头排序由 `render_th` 自绘（只在当前排序列显示箭头）；选择列平时显示系统文件图标（舒适 24 / 紧凑 16）、悬停/有选中时换复选框；行悬停浮出单行操作，舒适密度且停靠详情面板未打开时末尾多一个「详情」（`RowAction::Detail` → `DownloadView::show_row_detail`：先单选该行再开面板，否则面板的「跟随单选」会切回旧选中项；面板打开后单击行即切换详情，按钮隐藏）；已完成不画进度条，只有下载中（primary）与失败（destructive）着色；紧凑 30 单行 / 舒适 44 双行。侧栏状态项用语义图标（非文件夹），悬停状态项时图标位换成分类展开箭头（不占额外缩进列），分类子项仅比父项多缩进 `spacing.lg` 且悬停/选中底色铺满整行，计数为 0 不显示。
- footer 代理选择器（GPUI `downloads/components/status_proxy.rs`，Web `downloads/statusbar/ProxyControl.tsx`）：复用设置页的 `none/system/manual/auto`，只增量写 `proxy_mode`，保留已保存端点与认证；手动项显示服务器端点，不显示 URL userinfo。手动服务器或有效端口未配置时禁用该项，并提示「请先在设置中配置代理」；设置页仍可进入手动模式填写配置，footer 不擅自改写已保存模式。配置回流更新当前模式与可选状态，断线禁用，失败复用下载页错误横幅；系统代理指下载服务宿主的系统设置，Web 不读取浏览器电脑的代理。
- GPUI 批量导入与全局控制：所有窗口共享 `AgentClient` 的提交 gate；「全部暂停」先关闭新请求入口，已发送创建收到结果后再暂停已有任务，尚未发送的项保留在原提交流程与跨重连传输队列。「全部开始」成功才解除既有暂停；失败不把原本运行中的导入永久锁住。新建下载的普通链接由 `submission.rs::run_submission` 按 256 条一块走 `daemon.task.createMany`（表单共享选项只放 `common`，每块新 `batchId`）；结果不确定（Unavailable / Timeout）时用**同一** `batchId` 指数退避重发（2/4/8s，至多 3 次，服务端幂等），因此不暂停 gate、不弹中断通知；重发用尽则该块计失败、剩余块不再发送。非幂等提交（单条 `daemon.task.create`、建组、种子、捕获确认）保持旧规则：已发送但响应丢失的不自动重放，立即显示持久错误通知及可复制的链接，剩余项待重连后显式继续。进度与取消：`SubmissionHooks`（取消令牌 + 注入的定时器 + 每块一次进度回调）；超过一块的导入在下载页顶部显示进度条（每个导入一条，含重试等待文案与「取消」），无主窗口时先调出主窗口。取消在块边界生效，在途块给 3s 收尾以拿到准确计数，超时放弃（传输层跳过 ack 已关闭的未发送命令）；已创建任务保留，汇总提示「已添加 X / 共 N」。`keep_alive` 只保留当前桌面进程内的提交，不承诺退出应用后恢复导入列表。完整任务快照按 ID 线性对齐与清理，仅重建变化行，保持删除、终态清理、顺序和精确筛选/排序失效语义；`TasksChanged` 在控制器里整批追加、每个事件只推进一次结构代际。

- 启动与连接态：`AgentClient` 在 GPUI 初始化前就开始连接，连接失败前 5s 以 100ms 快速重试（覆盖回环重连、agent 冷启动 / 重启），之后指数退避。TCP 连接由 `service_bootstrap::connect_listener` 自行完成并区分 `Listening` / `Refused` / `TimedOut`：探测（拉起前的监听者探测、`wait_until_stopped`）固定 300ms（`PROBE_TIMEOUT`，超时按「无人监听」处理——Windows 对未监听回环端口约 2s 才报拒绝；已绑定未 accept 的端口由内核完成握手，算在监听）；真正建连从 300ms 起、连续超时逐轮加倍封顶 5s，被拒或连上即复位，避免杀软 WFP 过滤 / 高负载下回环 >300ms 时永远连不上并反复拉起 agent。WS 升级 + `system.hello` + `system.snapshot` 总时限 15s（agent 已 bind 未 serve 或挂死时不再永久卡在「正在连接」）。被拒 / 超时即单飞拉起 agent 并发 `AgentClientEvent::ServiceStarting`；无 bearer 且端口有人监听时只在 3s 宽限内不拉起（监听者可能是其他用户的 agent）；重读 bearer 后仍 401 = 监听者不是本用户 / 本数据目录的 agent（多用户同时登录、端点陈旧），按可重试处理并拉起本用户 agent（它会回退端口并重新发布端点），不再 `Fatal`。拉起失败可见（`service_bootstrap.rs::SpawnHealth` + `service_failure.rs`）：可执行文件缺失 / 被隔离 / 无权限，或子进程连续 3 次存活 <30s 即非成功退出（成功退出、存活 ≥30s、连上 agent 清零），暂停拉起（定位失败 10s、崩溃循环 120s 冷却后放行一次），发 `AgentClientEvent::ServiceFailed`（`Launch` / `Exited{status, startup}`，`startup` 取 bearer 同目录且不早于该次拉起的 `agent-startup-failure.json`），同一失败期只发一次；`service_notices.rs` 在主窗口弹不自动消失的 error 通知（原因、细节、`<agent 数据目录>/logs`），`SessionSignal::Fatal` 同样提示，收到快照即撤销。`AgentSession` 对连接态有 800ms 宽限（`OFFLINE_NOTICE_GRACE`）：启动时的首个快照、断线后的重连快照在宽限内到达，视图就不收到 `SessionSignal::Stale`、不显示「正在连接」只读态（期间命令排队、重连后送达）；本进程冷启动 agent 时首个快照的宽限放宽一次到 5s（`COLD_START_GRACE`，重连期间的重新拉起不放宽）；超时 / `Fatal` / `ServiceFailed` 才广播离线。`attach()` 只在已广播离线时标记视图只读。主窗口（含 `--minimized`、带链接参数的启动）在会话就绪（`is_settled`：有快照或已确认离线）后才打开——热启动首帧即完整数据、主题与语言，冷启动等到首个快照（最多 5s，到期才以连接态出现）。
- API 服务设置（`settings/sections/api.rs`）：监听端口回车 / 失焦提交，普通桌面模式自动切换监听；只有新端口的官方 RPC 握手验证及配置保存成功才更新端口、地址并显示一次性成功 Toast。请求期间禁用重复提交；端口占用 / 启动或保存失败显示对应本地化错误 Toast、输入恢复原端口，原服务继续可用。上述成功与错误反馈消费后清除，均不进入窗口顶部持续反馈条。启动环境固定端口时输入禁用。油猴脚本直接嵌入 `userscript/fluxdown.user.js`，复制时仅注入当前已生效端口与按需读取的用户访问令牌，凭据不进入快照或网页对象；`GM_xmlhttpRequest` 走 `/download*`，无需放宽 `/rpc` 鉴权或 CORS。

- 跨窗口刷新：`native/daemon/src/event_hub.rs` 在生产边界把队列、任务组、Webhook 投递列表转换为对应顶层 `DaemonEvent`，不可仅包装成 `DaemonEvent::Engine`（快照会更新，但监听顶层事件的已有窗口会漏刷）。消费者同时处理增量事件与 daemon 重连的 `DaemonSnapshotReplaced`；移动任务及删除队列迁移任务后，通过 `TaskQueueChanged` 同步任务归属与调度缓存，删除已选队列时主窗回退「全部」。新增状态事件需验证真实 sink 广播与多个消费者一致，不能靠操作后重开窗口或额外拉快照补救。
- `app/windows/`：`WindowRegistry`（`Global`）按 `WindowKey` 去重、`on_window_closed` 清理；应用显式设置 `QuitMode::Explicit`，禁止 GPUI 在非 macOS 默认的最后关窗自动退出绕过保活。**退出判定唯一入口**：最后一个用户窗口关闭 → `lifecycle::quit_ui`（只退出界面；延后一轮执行，`lifecycle::keep_alive` 登记的在途请求未完成前推迟退出；defer 真正执行时重查窗口数）。窗口边界记忆由 `windows/bounds.rs::RememberedWindow` 唯一登记，写设备本地 `desktop.window.*`（`agent.preferences.patch` + `sync:false`，同键 500ms 防抖、退出时落盘）。主窗口 / 设置 / 进度记位置、尺寸、最大化和显示器 UUID；自动完成窗口复用进度窗口记忆；其余可调辅助窗口只记同类共享尺寸。gpui 窗口坐标按平台约定（macOS 屏幕局部逻辑坐标，Windows / X11 全局逻辑坐标），不额外乘除 DPI。恢复时优先保存的显示器，无记录尊重调用方目标屏，保存屏断开则回调用方有效屏或主屏；旧无 UUID 记录仍按主屏解释。尺寸、原生 minimum 与整个矩形一并约束到目标 `visible_bounds`，不能仅凭部分可见就保留超大窗口；工作区小于 minimum 时工作区优先。只在真实边界变化时写偏好。主窗口关闭策略 `main::should_close` 只看 `shell.resident`：驻留只关窗，非驻留等同「退出」；原生关闭按钮与 ⌘W / 菜单关闭必须共用该策略，因为 `remove_window` 不触发 `windowShouldClose:`。
  - 已登记窗口的聚焦统一在 `WindowRegistry::open_or_focus` 内 `defer`：快捷键 / 菜单分发期间，活动窗口位于自身 update 栈内，`handle.update` 暂时失败不代表已关闭，不能据此清登记并重建（#845）。窗口登记只由实际 `on_window_closed` 清理；延后聚焦期间窗口已关闭则停止，不重建窗口。无 GUI 的 GPUI 回归测试覆盖自身窗口重复触发、跨窗口聚焦及关窗后重开。

### 云端连接与设备在线状态

PC 与 Web SPA 都消费 agent 的 `AgentSnapshot.cloud_connection` / `CloudConnectionChanged`（Web wire 为 `cloudConnection`），不自行连接 FluxCloud。它表示远程任务事件通道，与登录会话、本机 UI→agent 连接、daemon 下载核心连接及配置同步的 `sync.connected` 分别独立。

- `is_current` 只表示设备身份；登录或刷新资料成功不代表设备在线。
- 只有本机 agent 投影新鲜且云通道为 `connected` 时，才把设备名册中的 `is_online` 显示为在线/离线。断连时账户列表、详情、在线计数和下载目标显示状态未知，不保留旧绿点；LAN 状态只受本机 agent 连接影响。
- 设备区在云通道不健康时调用 `agent.remote.reconnect` 后刷新名册；响应 `{accepted:true}` 仅表示已请求重连，最终状态由事件驱动。健康时普通刷新不重建 SSE。
- 云设备离线或未知仍可下发排队任务，不据此禁用目标。顶部账户刷新仍只是资料/名册刷新。

### 开机自启与旧版迁移：agent `platform/autostart.rs`
- **已启用** = 本应用条目存在且未被系统级开关禁用：Windows `Explorer\StartupApproved\Run\FluxDown` 首字节奇数 = 用户在系统设置 / 任务管理器关闭；Linux `[Desktop Entry]` 内 `Hidden=true` 或 `X-GNOME-Autostart-enabled=false`；macOS（仅 agent）`launchctl print-disabled gui/<uid>` 把 `dev.zerx.fluxdown.desktop` 列为 `disabled`（旧系统 `true`）。登录项「允许在后台」由 BTM 维护、无公开 API，与 launchd 禁用表的对应关系未经官方文档确认。
- **应用内开启** 写条目并清除系统禁用标记（Windows `StartupApproved` 写 `02 00…`，Linux 整份重写，macOS 写 plist 后 `launchctl enable gui/<uid>/<label>`）；**关闭** 删条目（Windows 连 `StartupApproved` 值一起删）。agent `platform::autostart_state()` 把「未注册 / 已启用 / 被系统禁用」交给 Doctor 的 `autostart` 检查。
- **启动时自动迁移**（agent `migrate_legacy_autostart` → `retarget`：旧版指向桌面的条目改指 agent）只改写启动目标（`Run` 值 / `Exec` 行），**绝不**改系统级启用状态——不得复用 `enable`（强写 `StartupApproved=02` 会把用户在系统里关闭的自启重新打开）。
- 条目坐标：Windows 两端同用 `HKCU\…\Run` 值名 `FluxDown`（Flutter `"<FluxDown.exe>" --silentStart`、GPUI `"<fluxdown-agent.exe>" --autostart`，另见 `installer/windows/setup.iss`）；Linux Flutter `$XDG_CONFIG_HOME/autostart/FluxDown.desktop`（AppImage 指向 `$APPIMAGE`，不能用临时挂载路径），GPUI `fluxdown.desktop`；macOS Flutter 走 SMAppService 登录项（LaunchAtLogin，`--silentStart` 不会传入），GPUI 走 `~/Library/LaunchAgents/dev.zerx.fluxdown.desktop.plist`。

## 原生 iOS（`mobile/FluxDown`，SwiftUI · Liquid Glass）

当前 iOS 客户端，与 `mobile/Android` 共享同一 Rust 核心（`native/mobile`，UniFFI）与同一分层；视觉遵循 Apple 官方设计（设计稿 `docs/mobile-ui/ios/*`，本机草稿）：系统组件优先，Liquid Glass 只用于浮在内容之上的功能层（标签栏 / 底部附件 / 工具栏 / Toast / 范围条），内容卡片不叠玻璃；底栏主操作统一 `ToolbarItem(.bottomBar)` + `.borderedProminent`（系统渲染着色玻璃），不在工具栏项或内容里再用 `.glass*`。最低 iOS 26.1（`tabViewBottomAccessory(isEnabled:)` 所需：页面自带底栏或隐藏标签栏时经 `suppressesBottomAccessory` 隐藏活动附件；Xcode 27 / iOS 27 SDK；iOS 27 API 仅在壳层用 `#available` 渐进增强，如 `Tab(role: .prominent)` 新建标签）。全局搜索不是标签：各根页右上角按钮以 `SheetRoute.search` 呈现。

- **包结构**（本地 SwiftPM 包 `FluxKit`，与 Android 模块一一对应）：`FluxDomain` = `:core`（模型、`HostSession` 端口、`HostStore` reducer、`Format`、`L()` 文案、`Protocol/` 通用通道）；`FluxBridge` = `:bridge`（`RustHostSession` 适配 + `Mapping.swift`；进程级 `FluxBridge.openLocal/openRemote/shutdownLocal`）；`FluxRustBindings`（UniFFI 生成 Swift，只被 FluxBridge `internal import`，生成的 `HostSession` / `FluxCore` / `*Dto` 不外泄）；`FluxUI` = `:fluxui`（纯组件库，不依赖 FluxDomain：色彩令牌 `Color.fd*` 是唯一字面量处、分段图谱 / 速度波形 / 圆环按钮 / KindIcon / Toast / 范围条…）。模型避开 Swift 并发库重名：`DownloadTask`、`DownloadGroup`、`TaskQueue`、`TaskCategory`。

## 浏览器扩展（`fluxDown/`）与用户脚本（`userscript/`）

### 扩展（WXT，Chrome MV3 + Firefox MV3，Preact UI）
- **插件页面脚本（`fluxDown/background/page-scripts/` + `entrypoints/page-script-runtime.ts`）**：扩展充当 user script manager，经浏览器官方 `userScripts` API 注册插件 `contributes.pageScripts`，扩展任何位置禁止 `eval` / `new Function` / 远程 `<script>`（Chrome Web Store MV3 与 AMO §5 都要求）。`userScripts` 权限在 Chrome 与 Firefox 都放 `optional_permissions`，须在用户手势中 `permissions.request`；Chrome 138+ 另需用户在扩展详情页打开「Allow User Scripts」（更早版本为开发者模式），可用性探测用 `try { browser.userScripts.getScripts() }`。注册模型：每插件一个 `worldId`（`fd.` + identity，`@`→`.`），脚本注册 id `fd.<identity>.<scriptId>`；`configureWorld` 开 `messaging` 并设 CSP 禁止脚本内二次 eval；isolated 脚本注入「启动数据 → `page-script-runtime.js` → 插件源码」，main 脚本只注入插件源码、无桥；后台 `runtime.onUserScriptMessage` 靠每插件持久随机令牌认来源（`MessageSender` 没有 world 字段）。脚本源码始终从桌面拉取，扩展 storage 不留副本；同步由 `capabilities` 的 `pageScriptsSequence/Epoch` 变化、`onInstalled`（更新会清空用户脚本）、`onStartup`、选项页操作与「有已启用插件时」的 10 分钟 alarm 触发，桌面不可达时保留已注册脚本，插件不在索引里则注销。授权分两层：桌面端 `pageScripts` 权限走常规 consent；扩展端「每个插件首次启用」确认框一次，之后脚本新增 / 代码更新 / 匹配范围变化自动生效。桥 API 窄而固定（`download` / `addMedia` / `invoke` / `storage`），不得扩展到改写扩展自身行为（AMO 要求）。`invoke` 经 NMH `plugin_invoke` 走**每插件专用端口**（`utils/nmh-dedicated.ts`，同插件排队、空闲 30 s 断开）：`fluxdown_nmh` 中继与 agent 连接都是一问一答串行，慢处理器若走共享端口会堵住下载与能力探测。
- **通信**：桌面发行链路全平台走 NMH：扩展 →（stdin/stdout）→ `fluxdown_nmh` →（Windows Named Pipe / Linux-mac UDS）→ `fluxdown-agent` → daemon。消息 = 4 字节 LE 长度 + JSON。action：`ping`（只探不拉起）/`download`/`batch_download`（换行 join 单确认，按 700KB+1000 条分块防 1MB 帧上限，旧 App 回退逐条）/`warmup`（本地应答重叠冷启动）；协议 2 另有 `capabilities`/`capture_status`/`sniff_rules`（见 hosts-and-api.md「扩展协议 v2」），旧 App 自动降级为协议 1（不同步规则、不跟踪确认框、无解析插件判断）。
- **Android 浏览器**（Firefox for Android、Chromium 系 Android 分支）：没有 Native Messaging，`utils/download-dispatch.ts` 的「本机」通道按 `utils/platform.ts::isAndroidPlatform` 换成 `background/android-handoff.ts`——`utils/android-intent.ts` 构造 `intent:<原链接去 scheme>#Intent;scheme=…;action=VIEW;package=com.fluxdown.app;S.Cookie/S.Referer/S.User-Agent/S.com.fluxdown.extra.{FILE_NAME,HEADERS};end`（**不带** `browser_fallback_url`，原因见 pitfalls.md），命中 App 现有 http(s) / magnet / ed2k VIEW 过滤器，不依赖 `fluxdown://` 开关；优先在当前 http(s) 页 `scripting.executeScript` 导航，不可注入时退回交接标签页（`background/handoff-tab.ts`，与协议模式共用）。单向投递：可用性恒为可达、不轮询任务；分轨对 / POST / 其他 scheme 返回 `android_*_unsupported`（fallback 模式改投远程，否则按业务拒绝回退浏览器）。Firefox for Android 79+ 没有 `downloads` / `commands` 命名空间：拦截只剩 webRequest blocking，所有 `browser.downloads` / `browser.commands` 启动期访问必须经 `hasDownloadsApi` / `hasCommandsApi` 守卫（模块加载期抛错 = 整个 background 不启动），回退浏览器下载改为新标签页导航（bypass 放行，POST 只通知）。manifest 未声明 `gecko_android`，AMO 不向 Android 列出。
- **移动端 UI 裁剪**：扩展页面经 `ui/hooks/usePlatform.ts`（`desktopApp` = 探测完成且非 Android，依赖桌面 App 的入口只在它为真时渲染，避免手机上闪现；`shortcuts` / `contextMenus` 按 API 存在性）隐藏 NMH-only 与缺失浏览器 API 的入口：popup 任务页签（快速下载抽成 `ui/features/QuickDownload.tsx` 放进资源页）、页面脚本提示 / 设置页、交给桌面解析卡、规则同步卡与官方 / 插件 / 社区层筛选、连接诊断导出、本地任务通知、绕过键、取消回退 / 询问排除（`capture-tracker` 只走 NMH）、右键菜单、快捷键、fluxdown:// 协议（Android 一律 Intent）。嗅探、资源列表、浮钮、页内面板、链接抓取、远程模式在 Android 照常可用。内容脚本拿不到 `getPlatformInfo`，按 `(pointer: coarse)` 适配：浮钮在触屏上等同「常驻」并在点按媒体元素后显示 4s，弹层夹进视口；页内面板 / 悬浮点按窄屏与粗指针重排；`.fd-modal` 宽高夹进视口；设置页 `@media (max-width: 720px)` 侧栏变顶栏。
- **共享端口与连接状态**：background 只持一条常驻共享 NMH 端口（`utils/nmh-shared.ts`）。中继与 agent 连接一问一答串行，**队首请求超过自身时限即回收端口**（排在后面的请求注定超时；只是排在合法慢请求后面而超时的不回收），否则一次卡住会让任务面板 / 能力探测永久「未连接」直到 SW 重启。popup 与侧边栏的连接指示都取 background `getHostStatus`（共享端口 `capabilities`；fallback 模式本机不可达时远程可达也算已连接），UI 页面不得自开 `connectNative` 另立探活（agent 本地应答 `ping` 不经 daemon，会与实际下载链路不一致）。TabView 推送只限时 300 ms 等 handoff 探测，超时用上次结果，探测结果变化后 `ports.ts` 补推；资源列表不得被桌面端探测阻塞。
- **目录分层**：`rules/`（声明式嗅探规则引擎，纯模块：schema v1 / glob 与引擎 `url_glob_match` 同语义 / 校验与正则安全子集 / 求值器 / 内置包 `builtin.json` + fixtures）、`background/`（`startBackground()` 拆分模块；消息契约 `background/protocol.ts` 的 `MessageMap`，路由 `messages.ts`，`tab-view` 端口 150ms 合并推送）、`page/`（MAIN world 钩子 `hooks.ts` + 来源打标 `provenance.ts` + 两端事件契约 `bridge.ts`，detail 一律 JSON 字符串）、`ui/`（Preact 组件 / `--fd-*` token / features；内容脚本 UI 样式构建期内联：panel / sensor 为 `cssInjectionMode: "manual"`，`wxt.config.ts::inlineContentCss` 把依赖图里的 CSS 登记到 `ui/content-css.ts`，`createShadowRootUi({ css: contentCss() })` 注入，产物无 `content-scripts/*.css` 与 web_accessible_resources）。入口：`page-hooks.content.ts`（MAIN world 钩子；Chrome 与 Firefox 128+ 都经 manifest `world: "MAIN"` 声明式注入，`page-hooks-main.ts` 与 sensor 内联的 `injectPageHooks` 已随 Firefox 迁 MV3 删除）、`sensor.content.ts`（全帧 document_start：桥接、DOM 扫描、媒体元素跟踪、本帧视频浮钮）、`panel.content`（顶层帧悬浮球 + 面板）、`popup`/`options`/`sidepanel`。Firefox 构建为 MV3（输出 `fluxDown/.output/firefox-mv3`），background 是非持久 event page（manifest `background.scripts`）；仍保留 `webRequestBlocking` 阻塞式 `onHeadersReceived` 拦截；Firefox 允许用户撤销 `<all_urls>` 主机权限，popup / options 以 `HostAccessNotice`（`utils/host-access.ts`）提示授予。
- **规则来源与优先级**：local > official > plugin > community > builtin（`TIER_RANK`）。官方包源在规则仓 `zerx-lab/fluxdown-sniff-rules`（站点专属规则放官方包，`builtin.json` 只留通用规则），扩展随包附带已发布官方包的快照 `rules/official.json`（`bun scripts/sniff-rules/sync-repo.ts seed --repo <规则仓>` 生成，勿手改），`effectiveOfficialPack` 取快照与远程中 sequence 较新者；`compileBundled` = builtin + 官方快照，供内容脚本 / 页面钩子与远程包加载前使用。社区包由规则仓合并登记仓库（`community.<ns>.*`）与托管的 `community.misc.*` 生成；社区规则的 `extract` / `dom` 产出地址必须落在规则自身 `match.host ∪ pageHost` 内（`engine.ts::emitAllowed`），`mirror.hosts` 同理（`validate.ts`）。official / community / 吊销列表由 agent 验签下发，background `rules-store.ts` 经 `sniff_rules` 同步（启动 5s + 6h alarm + 手动），再经 `validatePack` 落 `storage.local`；社区包需有效吊销列表且未过期才生效，hard 吊销不可被用户覆盖。吊销列表只作内部机制，设置页「规则同步」与侧边栏诊断都不展示其条目（规则表仍显示吊销状态与「仍然启用」）。本地规则行「提交到社区」（`options/lib/local-rules.ts::communitySubmission`）改写为 `community.misc.*` 并按社区层预校验后打开规则仓预填 Issue 表单。设置页规则表可查看内置规则原文（`RuleTable.tsx::BUILTIN_RULE_PREVIEW`），`release.yml` / `test-package.yml` 构建时设 `WXT_HIDE_BUILTIN_RULES=1`，打包产物整段剔除该入口。扩展不写任何平台专属逻辑，站点解析交给桌面插件 resolver（`HandoffCard` 按 `capabilities.resolvers` 的 URL glob 判定）。
- **浮钮准确度**：MAIN world 钩子把 fetch / XHR / stream 读出的 buffer 按响应 URL 打标，并沿 `slice`/`set` 传播，`SourceBuffer.appendBuffer` 时归因到 MediaSource → 媒体元素（无标记时 3s 时间窗口归因；证据按导航代数隔离，SPA 换页后复用的 SourceBuffer 不带上一页 URL；导航代数由 MAIN 持有，sensor 只报 `sid` + 换页计数 `nav`，重注入的新 sid 只握手不换代）；background `media-binding.ts` 先比 exact 命中数、再比 temporal 计数、再比元素 rank 把候选绑定到元素（exact 必须压过任何 temporal；某地址已是别的元素的 exact 证据时不计入本元素的 temporal——推荐流同时预加载多个视频），正在播放的档位按 `trackFileKey`（路径末两段，忽略 CDN 镜像域名 / 前缀与签名）及同档备用编码轨（`alternateUrls`）识别；`view-model.ts` 分组为「当前播放 / 页面其他视频 / 未关联的媒体 / 文件」。元素换 MediaSource / 换直链或被移除时，tab-state 把上一播放会话归档为历史项（每 tab 12 个，标题取它播放时的标题，钩子 hid 变化 = 换了文档时丢弃），历史项参与关联但永不成为当前播放元素；被追加进音频 SourceBuffer 的完整文件按音轨处理（不单列为视频直链）。浮钮只展示绑定到指针下元素的候选，绝不回退整页媒体；按元素缓存上次候选，重新悬停立即显示。
- **页面探测恢复**（`background/probe.ts`）：Chrome 在扩展安装 / 更新 / 重载后不给已打开的页面补注入声明式内容脚本，旧 sensor 失效后只剩 webRequest。每个 sensor 实例有会话 `sid`（元素 key 前缀），`getPageConfig` / `mediaElementState` 登记到 tab-state（随快照持久化）；同帧出现新 sid 时旧实例的元素归档后删除，不认识的 sid 发增量会被要求 `resync` 全量重发。顶层帧缺会话的 http(s) 页面在加载完成 / 激活 / 产生媒体请求 / 打开面板时，先 `probe` 探测（活着的 sensor 应答后全量重发），无应答才 `scripting.executeScript` 依次注入 MAIN 钩子、sensor、面板（Chrome 与 Firefox MV3 相同）；每个文档最多注入一次，失败记 `unavailable`，不轮询、不保持长连接、不自动刷新页面。MAIN 钩子安装标记为 `{protocol, hid}`（旧版是布尔 `true` = 协议 0），已有任何标记都不重复包装；新 sid 握手时协议 ≥ 1 的钩子应答 `hooks` 并重放仍挂在元素上的 MediaSource 证据。扩展更新会清空 `storage.session`，已暂停的播放器不再发请求，background 按元素 exact 证据补报资源表缺失的地址（`unseenEvidence`）。钩子补装晚于页面播放（`late`）且当前播放元素毫无证据时视图为 `degraded`，面板提示刷新。
- **清单与分片归属**（`utils/media-candidates.ts`）：共享轨道文件的多份 DASH 清单（预加载 / 补全清晰度 / 换签名 / 内嵌状态 + 接口）合并为一个候选，同一分辨率按帧率档（≈30/60/120）合并编码；SegmentTemplate 已知的 `$RepresentationID$`/`$Bandwidth$` 展开后按模板匹配分片（任意扩展名）；HLS 播放列表正文由钩子解析（`utils/hls-playlist.ts`：子列表 + 分片目录，经 `hlsObserved` 存 tab 状态），主列表吸收子列表与分片。JSON 深扫得到、页面未请求的媒体地址记为 `api-scan`（低可信，未关联时默认隐藏）。
- **站点配置**：`utils/site-profiles.ts`（按 host 最长后缀命中：接管 default/never/always、嗅探、悬浮球、浮钮、保存目录）取代旧全局 `excludeDomains`，设置 v2 迁移在 `utils/settings.ts::migrateSettings`。
- **扩展连接诊断导出**：popup 底部与设置页「通用 → 连接诊断」提供「导出日志」，不依赖桌面 App 在线。`utils/connection-diagnostics*` 由 background 单写者串行持久化 NMH 连接失败、浏览器拒绝原因、请求超时/失败、重试和恢复事件；最多 200 条、按最近发生时间保留 7 天，相邻同类事件合并计数，后台重启可恢复。导出时仅 ping 探活（不拉起 App、不建任务），输出扩展 ID/版本、浏览器环境、模式/配置布尔摘要及事件 JSON；不复制完整设置、Cookie、令牌、下载链接、文件名或请求体，浏览器错误中的路径/凭据先脱敏再落盘。日志只在本机保存，由用户手动导出，不自动上传；content script 不可读写诊断日志。此导出与资源嗅探的页面资源调试日志分开。
- **三层拦截**（`background/intercept.ts`）：`onHeadersReceived`（缓存元数据 + Firefox `webRequestBlocking` cancel）→ `onDeterminingFilename`（Chrome 先发起 `downloads.cancel`，再调用 `suggest()` 释放文件名管线；取消成功才投递客户端，抹除下载记录在后台进行不挡投递）→ `onCreated+onChanged` 兜底（主拦截已按完整信息放行的下载标 `released`，兜底层不再重判；绕过令牌 / 熔断 / 总开关在等待元数据前同步判定；取消后立即投递，Firefox 抹除轮询在后台）+ 页面态 `page/hooks.ts` 抢先（`preempt`）。拦截总开关关闭时三组 listener 整体摘除（`setInterceptListenersActive`）。`suggest` 不支持 `cancel` 字段；取消失败保留原生下载，投递失败按 `fallbackOnReject` 回退浏览器；本机通道确认框被拒 / 失败经 `capture_status` 轮询按 `fallbackOnCancel` / `fallbackOnReject` 回退，同站 7 天内拒 3 次询问是否设为「不接管」。重定向下载以 `finalUrl` 为目标，原始 URL 保留用于请求事务缓存查找。
- **链接按下预热**（`entrypoints/sensor.content.ts::onLinkPress` → `messages.linkPress`）：浏览器要等对方响应头才把点击变成下载，按下 http(s) 链接时 background 按 `utils/settings.ts::isLikelyDownloadClick`（只认 `<a download>` 或扩展名命中生效拦截列表；总开关 / 站点 never / 排除扩展名 / 自身远程 Web UI 否决）加上拦截监听在挂、未熔断、无绕过令牌，调 `warmupNativeHost()`，让 App 冷启动与等待并行。只预热不接管；预热会拉起 App，普通网页链接不得触发。
- **右键「下载链接」走同一捕获路径**（`background/menus.ts` + `utils/link-capture.ts` 事务表 + `background/link-capture.ts` 单例）：Chrome 且拦截开启、App 未熔断时，http(s) 链接经 `downloads.download` 交给浏览器发起，`onDeterminingFilename` 按下载 id / 规范化 URL 认领后与点击下载一样取消并发送（浏览器定下的文件名 / 大小 / finalUrl / 请求头），跳过拦截开关与文件类型过滤，发送不带 `origin: "intercept"`、沿用菜单通道；兜底层对事务内下载让路。以下情况交还菜单直接发送原链接（改动前行为）：Firefox、拦截关闭、`download()` 失败、响应前中断（防盗链 403 等，浏览器发起的下载带不了 Referer）、浏览器拿到网页（`text/html` / xhtml）、20s 内拿不到响应头（超时后迟到的浏览器下载只取消）。
- **文件名取证**（`utils/filename.ts::extractCleanFilename`）：浏览器名（有扩展名）> URL 查询 `response-content-disposition` / `rscd`（`queryDispositionFilename`，与引擎 `naming::query_disposition_name` 同规则；GitHub release / S3 / Azure 预签名链接路径末段是对象 ID）> URL 路径末段。兜底层路径 A 的响应头缓存同时按 `finalUrl` 查（缓存键是 200 响应的 URL，重定向下载的原始 URL 只有 3xx）。
- **只能由浏览器完成的下载**（`utils/download-source.ts`，三层共用）：引擎只能按 URL 重放，非 http(s)/ftp 的 scheme（`blob:` / `data:` / `filesystem:` / 扩展 URL 等）一律放行；页面 Service Worker 在浏览器内合成的 http(s) 下载（流式保存、网盘、网页 IM）按「落在 SW 作用域内 + 无网络证据」放行。作用域由 MAIN world 钩子包装 `ServiceWorkerContainer.register/getRegistration(s)` 并在受控文档启动时查一次，经 sensor `serviceWorkerScope` 上报，background 校验与发送帧同源后登记（`background/sw-scopes.ts`，`storage.session` 持久）。网络证据 = `onSendHeaders` 见过该 URL 且不是 `Service-Worker-Navigation-Preload` 预载：Chrome 与 Firefox 都不为 SW 自行响应的导航触发 webRequest，SW 直通 fetch 会触发。Firefox blocking 层另对作用域内「无 `ip` 且非 `fromCache`」的响应标记为合成并放行（防御性，正常不会走到）。主拦截只在按完整元数据判定后才标 `released`；元数据不全或出错时撤掉占位，兜底层照旧接手。误判方向只会是交给浏览器下载。
- **浏览器下载可见反馈**（`background/browser-downloads.ts` + `ui/features/DownloadNotice.tsx`）：拦截开启时 `syncDownloadShelfState` 关闭整个 profile 的浏览器下载 UI（Chromium 只要有扩展关闭就不显示气泡与工具栏图标），放行给浏览器的下载会静默落盘。Chromium 上拦截开启期间：文件名确定后 500ms 仍 `in_progress`（被接管的已取消）→ started，`complete` → done，`interrupted` → 收起已显示的卡片。优先经 `tabs.sendMessage`（发起时的活动标签页，`frameId: 0`，`ContentMessage` `browserDownload`）在页面右上角显示提示卡，不依赖系统通知权限；页面不可见 / 无 sensor 时退回系统通知，同一下载两阶段走同一通道。卡片「在文件夹中显示」经 `showBrowserDownload` 只放行该标签页收到过提示的下载 id。Firefox 无隐藏 API，不注册。
- **热路径监听**：`onSendHeaders`（带 `extraHeaders`）只覆盖 `main_frame` / `sub_frame` / `xmlhttprequest` / `media` / `object` / `other`，`sniff.ts` 主框架 `onHeadersReceived` 带 `types: ["main_frame"]`——图片 / 脚本 / 样式 / 字体占页面请求绝大多数且从不产生下载，新增 webRequest 监听必须带 `types` 过滤；`tab-state.ts` 合并重复资源只在字段真有变化时触发持久化 / 视图重建 / 徽标刷新。
- **IPC 用户隔离**：agent 与中继分别在 `native/agent/src/nmh.rs::{socket_path_under,pipe_name_for}` 和 `native/nmh/src/main.rs` 的同名函数独立推导同一端点，两侧须同步。Unix 唯一 socket 为用户 home 下固定数据目录的 `<data_dir>/ipc/fluxdown.sock`（Linux `<data_dir>` = `~/.local/share/fluxdown/`，macOS = `~/Library/Application Support/fluxdown/`），`ipc` 目录 0700、socket 0600，agent 额外校验对端 uid；Windows 用 `\\.\pipe\fluxdown-<account>`，`USERNAME` 转小写后逐字节编码 `[a-z0-9]` 之外的字符为 `_xx`（下划线也编码），避免账户名清洗碰撞。无法确定 home / 用户名时端点不可用；Unix 不走会在沙箱中重映射的 `XDG_RUNTIME_DIR`。
- **NMH 注册写入**（`native/agent/src/nmh.rs::registry`）：Unix 启动脚本与清单都经「同目录临时文件 + rename」原子替换——旧文件即使属于 root（曾以 sudo 运行），只要目录属于当前用户就能换成用户自己的文件；目录本身被拒时 `register()` 返回 `RegisterIssues.denied`，启动自愈只记日志报错，Doctor「重新注册」请求授权把这些目录改回属主后以普通权限重写。中继属于当前用户却缺执行位时以普通权限补上。
- **资源嗅探**：webRequest 响应（`background/sniff.ts`）+ 页面 fetch/XHR/清单/JSON 深扫（`page/hooks.ts` + `utils/media-sniff.ts`）+ DOM 扫描与 `dom` 规则（`page/dom-scan.ts`），统一经规则引擎 `classifyResponse` / `isIgnored` / `dedupeKey` 入 `background/tab-state.ts`（按 tab 存 `storage.session`，SW 重启恢复，读视图前等恢复完成）；`track` 规则判为音轨的完整文件（非分片 / 清单）按 audio 入库，分离音轨被服务端标成 video/mp4 时不再冒充视频直链；徽标数 = 视图模型可见行数。**换页判定**（`utils/page-nav.ts`，content 与 background 共用）：replaceState / tabs.onUpdated 只在路径变化时清空（站点加载后补追踪参数不是换页；推荐流用 replaceState 换 `modal_id` 也不清空，预加载的下一条在切换前就已请求完，清空会丢失），push / pop / 新文档按 query 判定；同站换页时现有清单保留一代为「换页前清单」（自动连播预取的下一个视频），只在关联到播放元素后展示。
- Chrome ID 经 manifest key 钉住（匹配 NMH `allowed_origins`）；Alt+Shift+D 切换拦截，Alt+Shift+V 下载活动页正在播放的媒体（`background/downloads.ts::downloadPlayingMedia`）；回退到浏览器下载时对该 URL 放行 15s（`background/breaker.ts::allowBypass`，防回退再被拦截的弹窗循环）；声明零数据采集。
- **规则阶段扩展**（`rules/schema.ts`）：除 response / normalize / track / body / dom 外，`page` 阶段（`title` 取元素标题、`player` 指定浮钮排除容器）经 `PageConfig.titles/floatExclude` 下发 sensor；`request` 阶段 `headers` 为命中 host 补请求头（禁止凭据与连接控制头，只补浏览器记录缺失的名字）；normalize `mirror` 声明同一媒体的镜像域名组，泛用文件名（index / video / playlist…）跨域名且路径不同时只在同 host 或同镜像组内认作同一轨道；body `manifest` 按路径取 DASH JSON 结构。`dom` 模板字段 `value` / `text` / `page`（规则匹配所用的页面 URL）；命中元素是或包含已跟踪媒体元素时 hit 带 `elementKey`，产出资源归属该元素——解析插件借此把「视频页本身」声明为 MSE 播放器的下载源（示例 `packages/plugin-sdk/examples/youtube-down/rules.json`）。
- **元素事实**：sensor 上报元素标题（规则 > Media Session > title/aria-label）与 EME 加密（`encrypted` 事件 / `mediaKeys`），也会遍历 shadow root（MAIN world `attachShadow` 钩子 + `openOrClosedShadowRoot`）；关联到元素的候选用元素标题，加密或清单声明 DRM（MPD `ContentProtection` / HLS SAMPLE-AES、非 identity KEYFORMAT）标 `protected`，浮钮 / 面板 / 快捷键都拒绝下载。URL 证据没绑上、但媒体资源经 dom 规则声明了唯一现存元素的候选按声明绑定（`binding: "declared"`，暂停时也在浮钮里）；元素没有任何来源证据（Worker 内取流等）且页面只有唯一可下载候选时推断关联（`binding: "inferred"`）；`blob:` 整段下载的 src 经 `createObjectURL` 钩子还原为原始 URL。HLS 主列表无独立音频组时按 `EXT-X-STREAM-INF` 展开各档，产物统一 mp4。

### 用户脚本（`userscript/fluxdown.user.js`，Tampermonkey）
页面态**扩展替代**（不能/不愿装扩展的用户）。`GM_xmlhttpRequest` POST 到本机 RPC `:17800/download`（带 `X-FluxDown-Client` 头 + 可选 token），拦截 DOM 下载 + hook fetch/XHR/MediaSource 嗅探。局限：无法拦截内核发起（Content-Disposition）下载、仅非 httpOnly cookie。
