# 桌面种子与磁力确认

## 当前实现行为

本机主动打开 `.torrent` 或 magnet 时，在建立下载任务前选择名称、目录和文件。元数据预览不创建任务，不启动内容下载或做种；磁力解析允许必要的 tracker / peer 请求。上传元数据使用现有私有 BlobStore，由确认、取消或 TTL 清理。

|入口|行为|
|---|---|
|菜单、拖放、手动新建|显示确认表单；取消不建任务|
|系统文件关联 / magnet / FluxDown 深链|先问 agent 打开策略（`agent.capture.openPolicy`）：来源关联已关闭则忽略；免打扰开启时经原捕获入口按宿主默认选项静默创建；否则确认。agent 不认识该方法（比桌面旧的常驻 agent）时回到原捕获入口|
|扩展、用户脚本、RSS、CLI / API|保留各自捕获事务和无人值守策略|
|远端 magnet|保留既有远端分发，不切回本机预览|
|HTTP `.torrent` 链接|仍下载种子文件，不当作磁力或本地种子|

多个输入逐项确认，名称状态按项重置，迟到的同项预览保留用户输入。排着多颗时「取消」写成「全部取消」，另有「跳过」只放弃当前这颗。确认保留原草稿的队列、暂停、文件名与高级选项；显式确认字段优先。多文件种子改名始终作用于容器目录，即使只选一个文件也保留该文件扩展名；单文件种子改文件名。取消不修改上次成功使用的目录 / 分类偏好。整批结束后：窗口是为这批种子开的（宿主交来的输入）或已经建过任务，且表单里没有其他链接时关窗；表单提交时分流出来的磁力链全部建完任务后，按同一「稍后 / 队列」选择继续提交剩下的普通链接，有磁力链被跳过则停在表单。

文件区与引擎发起的 BT 文件选择窗口共用同一个勾选组件（`components/bt_file_picker.rs`：全部文件 / 取消全选、已选数量与体积、逐项勾选），文件夹树、连选、筛选等能力只在那里加一次；全不选时不能开始，未改名时不重复显示原始名称行。字段区按内容定高，只有超过 `max_h` 才在内部滚动（滚动包装层的坑见 `pitfalls.md` GPUI 节）。

磁力链的预览未就绪（解析中或失败）时提供「跳过预览，直接添加」：按草稿选项和当前目录走普通建任务路径，任务先进列表继续等元数据，文件选择回到任务开始后的选择窗口。本机种子文件没有这条路径。

## 实现边界

- engine `bt_preview.rs`：支持 v1 / v2 / hybrid 的临时元数据会话；复用正式下载的连接、I2P、tracker 汇报策略与 DHT 引导节点，会话启动沿用同一降级阶梯（双栈 → 仅 IPv4 → 关闭 DHT）。代理来源按 `BtConfig::session_proxy_url` 解析；系统探测与 SAM 地址解析在阻塞线程上完成。无监听、无会话持久化、无 payload 下载，取消 token 控制资源释放。
- daemon `magnet_preview.rs`：有界预约、超时与取消。`torrent_preview.rs` 校验 blob、目录、选择和改名；成功确认经原 actor / manager 建任务，校验时读入的种子字节直接交给建任务，不在提交锁内再读一遍。
- daemon `torrent_submission.rs`：blob ID 为一次性幂等键。独立 worker 持 owned guard 完成创建、记录 task ID 和消费 blob，不随 RPC waiter 释放而中止。结果缓存有 TTL 和数量上限；已消费且过期的 ID 拒绝重建。此保证不等同于跨进程永久幂等。
- `SLOW_DAEMON_METHODS` 同时包含预览、解析、确认和丢弃预览；取消预约不等待网络 worker。丢弃可能等待正在提交的 blob 锁，因此使用独立的慢方法通道。
- GPUI `new_download/torrent.rs` 与 `torrent/model.rs`：只负责表单状态、批次与结果展示。实际确认由 app `windows/new_download/torrent_confirmation.rs` 立即启动并登记 `lifecycle::keep_alive`；表单只是弱引用观察者，关闭后请求仍完成。成功通知归宿主，失败无法在表单呈现时由宿主打开错误反馈。
- `bt_custom_name` 与显式选择在建任务时持久化，支持暂停、队列和重启；SQLite / PostgreSQL schema 与迁移保持一致。
- URL 去重（`dedup_same_url`）：确认后的磁力任务以种子字节落库、`url` 为哨兵，去重候选额外取 `origin_url` 里的磁力链；同一条磁力链再次确认或走普通建任务都返回既有任务，纯种子上传仍不去重。

## 协议与镜像

protocol `torrent_preview.rs` 定义预约 / 文件预览 / blob 预览 / 确认 DTO；`daemon.rs` 的创建参数新增缺省 `btCustomName`；`agent.rs` 定义 `agent.capture.openPolicy` 的参数与结果（只读：不建任务、不产生待确认捕获）。确认携带完整草稿 options；服务端拒绝其中的种子或音频附件。磁力判定统一用 `capture_link::is_magnet_link`（`magnet:?`，与引擎同口径）。方法名与 DTO 同步 Web、Android、Swift；本次未增加 iOS 商店版 P2P 入口，未修改生成绑定。

没有新增 HTTP 路由、下载设置键或依赖；新 RPC 和可选字段为增量扩展，旧客户端保持原创建行为。

## 回归与验收

- 协议：Unicode 路径、原始文件索引、超过 2GB 的大小、缺省字段和完整草稿。
- 引擎：只取元数据、不注册任务、不写 payload；v2 / hybrid 经过真实本地 tracker、SOCKS5 与种子端；tracker-only 与 peer 代理；I2P 与汇报策略映射；会话候选阶梯与引导节点；单选多文件改名保留扩展名；确认后的磁力任务参与 URL 去重。
- daemon：无效选择不进 actor；失败保留 blob；并发确认 / RPC waiter 丢弃后重放只创建一次；等待 discard 锁时快速查询可用；预约取消、超时和容量回收。
- 桌面：批次名称隔离、远端 magnet、队列 / 暂停 / 高级选项、跳过预览的请求构造；打开策略的三种去向与旧 agent 回退；真实 WebSocket 暂停门下确认排队、策略请求与预览取消不受阻。
- 保留人工验收：真实系统关窗、冷启动关联、外部免打扰两态、实际进度 / 错误窗口、确认框与 BT 文件选择窗口共用组件后的实际布局、移动端平台构建、真实 I2P SAM 网络。纯模型与传输测试不能替代这些项目。
