## HTTP API（`native/api`，`fluxdown_api`）

一个端口（桌面默认 17800 **仅 127.0.0.1**；headless `fluxdown-agent --server` 默认 `[::]:17800` 双栈）、一个 axum 服务器，多组按配置独立启停的路由。agent 宿主：开关经 `agent.gateway.patch` 热更新（`ApiRuntimeSwitches` + `TokenCell`），桌面端口修改先启动同一 router 的新监听并以官方 Bearer `/rpc` 握手验证，再保存配置与端点、停止旧监听；失败保留旧服务，既有官方 WS 与 daemon 下载不因端口切换断开。`lanEnabled` 仍下次启动生效，server / 环境固定监听地址不可在 UI 改端口。

| 路由组 | 端点 | 开关（config 键） | 鉴权 |
|---|---|---|---|
| 探活 | `GET /ping` | 总开关 | 无 |
| 脚本接管 | `POST /download`、`/download/batch` | `local_server_takeover_enabled`（默认开） | `X-FluxDown-Client` 头 + 可选 token |
| aria2 兼容 | `POST /jsonrpc`（36 方法）+ `GET /jsonrpc`（WS 升级，`jsonrpc_ws.rs`：RPC + `onDownloadXxx` 通知推送） | `local_server_jsonrpc_enabled`（默认开） | 可选 token（`X-FluxDown-Token` 或 `params[0]="token:xxx"`） |
| 管理 API | `/api/v1/*`（info、tasks CRUD+pause/continue[all]、queues、resolve/preview、groups CRUD+pause/continue、plugins list/install/install-dev/enabled/settings/**auth**（begin/poll/cancel/logout/status）/uninstall + ignore-plugin-retry、**site-auth** list/save/get/delete（`GET /site-auth/{site}` 回传明文密码，仅定向查询用于编辑表单回填）、market list/install、**rss** CRUD+refresh+items+items/action+validate） | `local_server_api_enabled`（桌面默认**关**；server 强制开） | **强制** token（Bearer 或 `X-FluxDown-Token`） |
| MCP | `POST /mcp`（Streamable HTTP 无状态子集，协议 2025-06-18；12 工具：download_add/list/get/pause/resume/pause_all/resume_all/remove + queue_list + rss_list/rss_add/rss_remove） | `local_server_mcp_enabled`（桌面默认关；server 默认开） | 同管理 API token |
| OpenAPI | `GET /api/v1/openapi.json`（utoipa 3.1，含漂移守卫测试） | 随管理 API | 无 |

- **`ApiHost` trait**（`service.rs`）：必需方法（list/get/create/delete/pause/continue task、pause/continue all、list_queues、submit_external）+ 可默认降级方法（config/plugins/market/groups/resolve_preview/subscribe_task_events/…）。`UNKNOWN_ENDPOINT_MESSAGE` 区分未注册路由 404 与资源 404。
- **鉴权与浏览器门禁**（`auth.rs`、`server.rs::browser_origin_guard`）：常量时间比较；接管需非空 `X-FluxDown-Client` 头；管理/MCP 强制非空 token（403）。默认不返 CORS 头；`/jsonrpc`（POST 与 WS 升级）和 `/download*` 的 `Origin` 仅放行扩展源或与 `Host` 同源的请求，其余 403，堵住不触发预检的简单 POST/WS。不带 `Origin` 的非浏览器客户端不受来源门禁影响。桌面默认绑 127.0.0.1（`local_server_lan_enabled` 可改绑 0.0.0.0）；仅回环监听时所有核心 API 请求的 `Host` 须为 127.0.0.1 / localhost / [::1]，防 DNS 重绑定，LAN/server 模式不强制此限制。
- **桌面对外暴露自动补密钥**（`agent/src/gateway.rs::ensure_exposed_auth_token`、`runtime.rs`）：LAN 或 CORS 任一开启、且接管或 aria2 任一开启时，空用户 token 自动生成并持久化；已有 token 保留，暴露面仍在时显式清空也会补回。启动与 legacy 迁移后同样补齐；headless 不调用该策略，空密钥必须保留为首次设置状态。
- **CORS 豁免开关**（`local_server_cors_allow_all`，默认 false）：开启后 `cors_and_preflight` 对预检与真实响应发 `Access-Control-Allow-Origin: *`（预检另带 `Access-Control-Allow-Private-Network: true`、`Allow-Headers` 回显），等价 aria2 `--rpc-allow-origin-all`，并显式放开上述 `Origin` 门禁，但不取消回环 `Host` 校验或 token 校验。代价是任意网页可探测端口，并在持有 token 时调用兼容 API；aria2 直接建任务、没有确认框，脚本接管也可能按免打扰设置静默建任务，不能把确认框当作通用防线。
- **语义区分**：脚本接管 → 外部下载流程（桌面可确认或免打扰静默建任务；headless 直接建任务）；aria2 `addUri`/管理 `POST /tasks` → 直接建任务返真实 ID（无确认框）。`takeover.rs` 的 batch 两形态合并为单 `DownloadRequest`（url 换行 join）。
- **批量 RPC**（`jsonrpc.rs::handle_jsonrpc/system_multicall`）：aria2 `/jsonrpc` 接受顶层调用数组，逐项顺序执行并逐项返回；`system.multicall` 各子调用各自携带 `params[0]="token:xxx"`（或共用有效 token 请求头），不是只给外层信封放 token。名单方法免 token 鉴权不绕过 headless 首次设置门禁。agent/daemon `/rpc` 一帧只接收一个 `RpcRequest`，并发调用靠独立请求 ID，不接受顶层数组。
- **daemon WebSocket 普通调用**：等待 actor/DB 时继续排空事件广播和发送慢调用回执；当前普通调用完成前不读取下一条请求，保留 create/pause 等命令的 FIFO 顺序。不得把普通调用直接 `await` 在接收分支内阻塞整个事件循环，也不靠增大广播容量掩盖堵塞。
- **事件转发与落后合并**（协议 v15；daemon `http.rs` + `event_pump.rs`、agent `gateway.rs` + `event_pump.rs`，含进程内 `LocalConnection`）：每个连接由泵任务及时把广播帧收进 `fluxdown_protocol::coalesce::FrameQueue`，独立写任务独占套接字（RPC 应答 / 关闭帧走有序通道，事件逐帧取出、只序列化一次）。订阅者跟得上时不合并；落后时同一实体「后帧完整取代前帧」的事件（同状态 `TaskProgress`、带分段的新 `TaskRuntimeChanged`、`SegmentProgress`、`RuntimeStatsChanged`、队列全量 / 增量）在队内合并，积压被实体数封顶；中间有触及同一任务的帧或整体替换帧时不合并。取出的帧带 `previous`（覆盖区间 `(previous, sequence]`），所有消费方按 `judge_frame` 判定（覆盖区间可越过游标）。合并后待发帧超过 16384 或广播接收端自身 `Lagged` 才回退 `4009 event-gap` 并 warn 带原因；agent 的 daemon 链路断开时 warn 记录关闭码 / 序号缺口等原因。握手期缓冲上限 65536 帧。
- **队列顺序增量**（协议 v15；engine `queue_order.rs::QueueOrderPublisher`）：引擎为每个排队任务分配排序键 `order`（入队即定，队首出队不改其余键；尾部追加 = 末键 + 2^20，头部插入 = 首键 − 2^20，中间取等距键），250ms 节拍与立即发布点只发相对上次已发布键表的差异 `WsServerMsg::QueueOrderChanged{removed, added}`，顺序不变不发；首次、用户调序、无空位、队列清空或键越过 2^52 时整表重排并发全量 `QueuePositionsChanged`（`QueuePositionDto.order` 升序、`position` = 名次）。各 reducer 用 `fluxdown_protocol::apply_queue_order`（先删后按键插入、重写名次）。
- **任务批量变更 RPC**（`protocol/src/{method,daemon}.rs`、`daemon/src/{service,actor}.rs`、`web/src/lib/rpc/methods/daemon.ts`）：`daemon.task.pauseMany/resumeMany {taskIds}` 与 `daemon.task.deleteMany {taskIds, deleteFiles}` 一次提交整批；daemon 去重、忽略未知 ID、空列表为空操作，暂停 / 恢复批处理末尾统一推任务快照。Web 本地任务批量操作复用它们，不逐任务并发挤满 agent 的普通 daemon 通道，也不把这些方法误写成 `/rpc` 顶层数组。
- **批量删除**（`engine/src/download_manager.rs::delete_tasks_batch`、`db.rs::load_deletion_facts`，协议 v12）：删除所需库内事实（「文件已存在」决定、独立音轨、衍生产物、同名产物归属）整批预读，不逐任务查询；文件清理并发（64）、单任务限时 30s；清理失败的任务单独保留、其余照删，结果 `BatchDeleteOutcome{deleted, failed}`，有失败时 RPC 报错。提交后经 progress reporter 发**一条** `DaemonEvent::TasksDeleted { taskIds }`（排在这些任务已入队的进度帧之后；= 按序逐条 `TaskDeleted`，各端 reducer 整批一次移除），不再逐任务发 `status=4` 删除哨兵，也不再追发全量任务快照（`deleteMany` / 删组 / 失效文件清理同此）。单任务 `daemon.task.delete` 仍是哨兵 + 快照。GPUI 按 256 个一块顺序下发 `deleteMany` 以显示进度、可取消（`crates/downloads/src/deletion.rs`，见 clients.md）。
- **批量建任务 RPC**（`protocol/src/{method,daemon,event}.rs`、`daemon/src/{service,actor,event_hub}.rs`）：`daemon.task.createMany {batchId, common, items[{url,fileName,checksum}]}`（协议 v11）一块 ≤`CREATE_TASKS_MAX_ITEMS`（512）条，共享选项只传一次（`common` 的 url / fileName / checksum 必须为空，种子 / 音轨 / method / body 不支持，违反即整块 `InvalidArgument`）；daemon 一次解析默认目录与队列，引擎整块单事务落库，返回与 `items` 同序的 `results[{taskId?|error?}]`（逐条拒绝不影响其他条目）。按 `batchId` 幂等（`task_create_batches` 与任务行同事务），结果不确定时客户端原样重发即可。整块只发一条 `DaemonEvent::TasksChanged(Vec<TaskDto>)`（= 按序逐条 `TaskChanged`；protocol reducer、agent `task_events`、mobile 投影、GPUI、Web `apply.ts` 都按此展开），逐条 `TaskNotice` 照旧。不是慢方法，走 agent `Lane::Daemon`；块大小要让单次 actor 操作保持在毫秒级，避免挡住暂停 / 恢复。
- **批量创建的事件成本**：`task.create` 不逐条发送全量任务表。引擎在配置落库、启动下载或探测之前发布内部 `TaskChanged`（批量为 `TasksChanged`）完整事实，daemon 映射为同名 wire 事件；全量快照留给连接初始化、重同步和显式批处理。队列普通追加增量维护占用，位置全量事件只在 dirty 时由 actor 每 250ms 合并发布，队列清空和全部暂停立即收敛；`(queue_id, queue_order)` 索引避免创建时扫描历史任务。
- **全局速率**：daemon `event_hub.rs::RuntimeAccounting` 按实际观测到的传输字节统计，而非加总活跃任务 EMA；短文件的完成帧仍计入。每个进度帧的增量按「该任务上一次采样（或转为活动）→ 本帧」均匀摊到 100ms 桶（最长摊 1s，字节守恒），速率 = 结束于 now 前 700ms（单任务进度帧 ≥500ms 一帧，窗口内必已上报）的 2s 窗口均值，新一轮流量只从其首桶起算不被空闲稀释；速率每 500ms 才重算 / 重发一次。因此逐 500ms 成块上报与上万个小文件连续完成都读作平直速率，代价是约 0.7s 的显示滞后，停止后约 3s 归零。恢复、截断重传及采纳已有文件通过引擎内部传输基线区分，已存在字节不算新流量；先缓冲后按序写盘的协议（HLS）由引擎在转发帧前发宿主本地 `TaskTransferred`（body 接收字节），该任务按这些字节计流量，进度帧的落盘跳变与收尾最终大小只推高水位，任务离开活动态或遇显式基线后恢复按进度增量统计；不新增 wire 字段。活动与等待数增量维护并即时发布，衰减节拍只处理内存中的未过期流量，不扫描任务表或磁盘。
- **配对 v2**（`link/src/pairing.rs`、`protocol/src/daemon.rs`、`api/src/server.rs`）：`/api/v1/link/pair/hello → reveal → confirm`；hello 只提交 `sha256(eph_I || nonce_I)` 承诺，响应方回本次会话的临时值后发起方才 reveal，核对承诺并验证完整转录签名后两端才展示 SAS；双方肉眼核对并批准才入册。版本必须严格相等（当前 2），缺版本按 0 处理并拒绝，不兼容无承诺的旧握手、不降级；reveal 承诺不符或超过 30s 即作废，不能重试旧会话，confirm 不能跳过 reveal。配对路由以一次性码/会话/SAS 而非用户 API token 守卫。
- **配对即授权远程控制**（用户 2026-10-22 决定）：hello 可选 `requestControl`，为 true 时 `hello_message` 在 addrs 后追加 `framed("fluxdown-link-control-v1")`（false 时与旧字节逐一相同，配对版本仍为 2），进入转录 / SAS / 链路密钥；发起方请求控制前读对端 `/ping`，无 `linkControl >= 1` 即 `pairingVersionMismatch`、不发 hello。响应方入站请求带 `requestsControl`，四端批准弹窗显示「请求完全控制」警示；批准后响应方记录 `grantsControl`、发起方记录 `controllable`（`PeerRecord` / `LinkDeviceInfo`，重新配对取本次结果）。发起方 `agent.link.controlCredential {fingerprint}` → `fdl1.<发起方指纹>.<b64url(HMAC-SHA256(link_secret, "fluxdown-rpc-control-v1\n"+发起方指纹+"\n"+响应方指纹))>`，作为 `/rpc` 与 server 模式 `/api/web/*` 的 Bearer（server 模式计入同一失败节流；桌面模式在 link 服务存在时接受）。设备会话 `allow_local_platform = false`（桌面模式下拒绝 `agent.platform.*`、不下发 `agent.openTaskFiles`）。**会话撤销**：设备记录变化（解除 / 被对端撤销 / 重新配对 / 授权变化）或访问密钥变化后，已建立的 `/rpc` 会话重新校验，失效即以 1008 `credential-revoked` 关闭（发起改密钥的会话除外，其记住的值随之更新）；客户端重连得到 401。
- **配对流程细节**：`agent.link.pairFinish {accept:false}` 在同一 token 的确认仍在等待对端表态时 = 中止（立即通知对端放弃，在途调用以 `pairingSessionExpired` 返回）；`LinkPairingCodeDto` / `LinkPairingRequestDto` 带 `ttlMs`（生成时刻剩余毫秒），客户端以「收到时刻 + ttlMs」倒计时，0 / 缺失才回退 `expiresAtUnixMs`（避免主机与客户端时钟偏差）；`agent.link.stopPairing {code?}` 带码时只作废仍是当前码的那张（多客户端互不干扰；发现开关仍是进程级）。错误：对端未在决策窗口内表态 = `pairingTimeout`，数据面 401 `clockSkew` = `peerClockSkew`。数据面另拒绝时间戳早于本进程启动时刻的请求（防重启后重放，代价是落后的发送方在本机启动后最多 120s 内被拒）。`FLUXDOWN_LINK_ADVERTISE_ADDR` 存在时即使监听回环也视为可达。
- **aria2 纯映射**（`aria2.rs`）：GID↔task_id 编解码、`METHOD_NAMES`=36、`NOTIFICATION_NAMES`=6、业务错误统一 `code:1`。

## 宿主与客户端 crate

### `native/mobile`（原生 Android/iOS 的 UniFFI 入口）
`FluxCore` / `HostSession` 提供本机与远端主机会话。本机复用进程内 daemon 与 agent 嵌入模式，远端通过 WebSocket `/rpc`；握手、游标、重同步与重连只在 Rust 实现，Kotlin / Swift 应用已接受的信号。工程与生成命令见 `clients.md`「原生移动端」及「原生 iOS」。

### `native/cli`（`fluxdown_cli`，二进制 `fluxdown`）
aria2c 风格。命令：ping/info/add(get)/list(ls)/status(stat)/pause/resume/rm/pause-all/resume-all/queue/watch/**config**(set/unset/get/list/path)。
- **A 模式**（默认）：typed HTTP client（复用 api `routes`+`types`），连运行中的 App/server。
- **B 模式**（`add --local`）：本进程内嵌 `fluxdown_engine::Engine`（`NoopSink`/`NoopSelection`）独立下载至终态，共享同一 SQLite（安装模式）。Ctrl-C → 暂停 + 退出码 7。
- env：`FLUXDOWN_URL`（默认 `http://127.0.0.1:17800`）/`FLUXDOWN_TOKEN`；`--json`；`K/M/G/T` 按 1024 解析；`.no_proxy()` 直连回环。退出码：0/1/2/3/5/7/24/32（aria2 风格，`exit.rs`）。

### `native/nmh`
浏览器 Native Messaging Host **中继二进制**（`com.fluxdown.nmh`）。浏览器 ↔（stdin/stdout 4 字节 LE 长度 + JSON）↔ nmh ↔（每用户 Named Pipe / 私有 UDS）↔ agent。同步单线程；懒连 + 重连；除 `NO_LAUNCH_ACTIONS`（ping/tasks/task_op/open/reveal/capabilities/capture_status/sniff_rules/page_scripts/page_script_source/plugin_invoke）外未连接时自动拉起 App（50ms 轮询至 10s）；`warmup` 本地应答重叠冷启动；1MB 帧上限。
- **扩展协议 v2**（`native/agent/src/nmh.rs`，`EXTENSION_PROTOCOL_VERSION = 2`）：严格一问一答，应答可带 `data`。`download`/`batch_download` 的 `data` = `capture.submit*` 返回值（`taskIds` / `transactionIds`）；`capabilities` 返回动作表、`pluginsSupported` 与带 `resolverUrls` 的插件（来自 `PluginDto.resolver_urls`）；`capture_status` 查确认框事务结局（`CaptureService::statuses`：pending / accepted / rejected / failed / unknown，结局环形保留 1024 条）；`sniff_rules` 返回 agent 验签后的嗅探规则包。旧 App 应答 `unknown action: capabilities` → 扩展按协议 1 降级。
- **页面脚本动作**（`native/agent/src/nmh.rs`，协议版本仍为 2，新动作靠 `capabilities.actions` 发现）：`capabilities` 的 `data` 另带 `pageScriptsSequence` / `pageScriptsEpoch`（daemon 无该方法 / 查询失败 / epoch 为空 → 均为 `null`）；`page_scripts` 返回 `PluginPageScriptsDto` 索引；`page_script_source { identity, id }` 返回源码 DTO，序列化后 > 900 KiB 报 `page script too large`；`plugin_invoke { identity, name, args, pageUrl }` 转 `daemon.plugin.pageInvoke`（应答 `PluginPageInvokeResultDto { value, createdTaskIds, resumedTaskIds }`：engine `quickjs_host` 在页面调用执行期间把 `flux.tasks.create` / `resume` 成功的任务记到这次调用，视图 / 命令 / 事件 / 定时器 / 调用返回后的悬空 Promise 都不记），`data = { value }`，开始的任务交 `CaptureService::announce_page_started` 按单任务静默捕获规则登记提示窗口。`NO_LAUNCH_ACTIONS` 在 `native/nmh/src/main.rs` 与 agent 两处各有一份，加动作要同改。

### `native/daemon` + `native/agent`：设置面 JSON-RPC（GPUI 客户端唯一入口）
方法名、DTO 与错误码全在 `native/protocol`（`method.rs` / `daemon.rs` / `agent.rs` / `daemon_config.rs`）；GPUI 设置页只经 agent `/rpc`（默认 `ws://127.0.0.1:17800/rpc`，实际端点由 bearer 同目录的 `gateway-endpoint.json` 发现，见下方「本机端口与端点发现」），`daemon.*` 由 agent 透明转发。
- 本机协议基线由 `protocol/rpc.rs` 的版本常量控制；新增严格事件枚举（如 `CloudConnectionChanged`）即升版本，拒绝不能解析这些事件的旧进程混用，更新时 UI/agent/daemon 必须一起重启——版本不兼容且对端已通过传输鉴权时，可在 `system.hello` 前发 `system.shutdown` 替换旧进程；新版 agent 对不支持挑战握手的旧 daemon 不发送长期 token，而由 supervisor 终止 stale daemon 后拉起新版本。每进程替换有界。`task_activity.rs` 定义任务运行态与活动 DTO；`daemon.task.activity {taskId, beforeId?, afterId?, limit?}` 查询持久历史，两种游标互斥、页内 ID 升序，返回保留范围、更多页及截断信息。实时 `TaskActivityAdded` 仅在提交后广播，`TaskRuntimeChanged` 同时更新快照。`daemon.task.speedHistory {taskId}` 返回 `TaskSpeedHistoryDto | null`（全程速度曲线与均值 / 峰值 / 下载用时，下载中取内存最新值）；无推送事件，各端详情「速度」页可见且任务下载中时每 2s 重拉、离开下载态补拉一次，旧主机无此方法按无数据处理。
- **daemon ↔ agent 双向认证**（`protocol/{handshake,digest}.rs`、`daemon/src/{rpc,http}.rs`、`agent/src/daemon_client.rs`）：新版 agent 仅以 `daemon.token` 作 HMAC-SHA256 密钥，不发送长期 token，WS 升级头不带凭据（带 `Origin` 的升级 403）。`system.hello` 之前，agent 发 `system.auth.challenge {clientNonce}` → daemon 回 `{serverNonce, serverProof}` → agent 验证服务端证明后发 `system.auth.prove {clientProof}`。认证前只放行这两个方法；其余（含 hello/shutdown）拒绝并断开；10s 超时、认证中连接最多 16、认证前帧最多 4KiB。daemon 的「握手前 shutdown」指认证后、hello 前；agent 的 UI Gateway 则仍在 hello 前受理已通过升级鉴权的 shutdown。
- **daemon HTTP 会话凭据与旧版兼容**：新版 agent 对 `/blobs`、`/files`、`/exports` 只发送两端各自派生的 `http_credential(token, clientNonce, serverNonce)`，不经 WS 传输，连接断开即撤销；`DaemonClientConfig::http_session()` 无凭据时按 daemon 不可用处理，绝不回退长期 token。daemon 作为校验方仍接受旧 agent 的有效静态 Bearer（WS 升级头与 HTTP），仅为包已更新但旧进程仍常驻时保持可用；新版 agent 不向旧 daemon 降级发送 token。
- **本机端口与端点发现**（文件契约单一事实源 `protocol/src/local_service.rs`：`LocalEndpoint` / `AgentStartupFailure` 与三个文件名）：**默认端口宽松、显式地址严格**。agent 桌面默认配置（非 `--server`、无 `FLUXDOWN_AGENT_BIND`）绑定已保存端口遇 `AddrInUse` / `PermissionDenied`（Windows Hyper-V / WSL / Docker 动态排除区间返回 WSAEACCES 10013）即改绑同接口系统分配端口，实际端口写回状态（与设置页改端口同一语义，`portEditable` 仍为 true）并原子发布 `gateway-endpoint.json`；daemon 未设 `FLUXDOWN_DAEMON_BIND` 时同理回退。独立 daemon 取得 `daemon.lock` 后删除旧 `daemon-endpoint.json`（`daemon.token` 同目录），控制面绑定后原子写入实际地址，退出时删除；嵌入式（移动端）不发布。显式地址（`FLUXDOWN_BIND`、`FLUXDOWN_AGENT_BIND`、`FLUXDOWN_DAEMON_BIND`）绑定失败即启动失败，错误带地址。supervisor 只在显式 `FLUXDOWN_DAEMON_URL` 时把同一地址经 `FLUXDOWN_DAEMON_BIND` 交给 daemon，否则不干预该变量。agent `DaemonClientConfig::discovered` 每次连接前解析目标并读取 `daemon.token`（token 未生成 = 未就绪，不连接，Gateway 不再等 token 就开始服务）：已发布端点优先；未发布时本进程拉起的 daemon 仍存活 → 等它发布（不碰默认端口上可能属于别的用户 / 程序的进程），否则仅当本数据目录 `daemon.lock` 被持有（旧版 daemon 只监听默认端口、从不发布）才连 `127.0.0.1:17801`。已发布端点上连接被拒 / 对端不认识挑战握手 / 证明不了 token = 端点过期，按拒绝拉起 daemon；默认端口上证明不了 token = 另一用户 / 数据目录的 daemon，等本数据目录的 daemon 发布，均不致命。agent→daemon 建连 + 认证 + hello + 快照总时限 30s、握手前 `system.shutdown` 10s；daemon HTTP（`/blobs`、`/files`、`/exports`）的基址与会话凭据一起由 `HttpSession::access()` 给出，随重连跟随新端口。桌面模式 agent 在 Gateway 开始服务前任一步失败写 `agent-startup-failure.json`（`kind` = `gatewayBind` / `dataDir` / `other`，`detail` 为错误链，`atMs` 供读取方排除旧记录），开始服务即删除；server 模式不写，失败只进 stderr / 日志。
- **慢方法共享清单**：`protocol/src/method.rs::SLOW_DAEMON_METHODS/is_slow_daemon_method` 是 daemon 与 agent 唯一判定源；daemon 慢调用每连接有界并发（最多 16），agent 放入独立 `DaemonSlow` 通道（最多 8），普通 daemon 命令同道串行以保持顺序，慢网络/安装不阻塞暂停、恢复和设置写入。不要在传输层另建清单；批量 aria2 RPC 与 `/rpc` 多请求并发不是同一契约。

### 云设备在线通道

`RemoteTaskService` 拥有设备在线通道；登录会话和配置同步不能替代在线判定。**通道优先 WebSocket**（`GET /api/v1/tasks/ws?deviceId=…`，生产为 wss；仅 `Authorization: Bearer` 头鉴权，令牌不进 URL）：任务事件、心跳 `{"type":"ping"}`（连接后立即发，之后每 30s）与应答 `{"type":"pong"}` 都在这一条连接内，不再产生 HTTP 请求；协议细节与时序以 FluxCloud 服务端实现及 `native/agent/src/{cloud/client.rs,remote.rs}` 为准。WS 专用 `ws_http` 客户端 `.http1_only()`（Upgrade 只存在于 HTTP/1.1）且 `redirect(none)`（3xx 不跟随，按中间层吞掉 Upgrade 处理），升级后 `WebSocketStream::from_raw_socket`，接收单消息/单帧上限 1 MiB，握手 401 走与 SSE 相同的单飞刷新后重放一次。**粘性回退 SSE 1 小时**（`ws_fallback_until`；SSE `GET /tasks/events` + HTTP 心跳 `POST /tasks/presence`），触发条件两类：① 握手响应被判定「不支持 WebSocket」（2xx/3xx、404/405/426/501、400/403 且正文非 FluxCloud `{code}` JSON、101 但 `Sec-WebSocket-Accept` 不匹配或缺 `Upgrade: websocket`；只看握手响应）立即回退，`CloudError.code = "websocket_unsupported"`，并在同一次尝试内改走 SSE；② 握手可达但通道不可用，**连续 3 次**（`WS_UNUSABLE_THRESHOLD`）任一情形即回退：101 成功但在第一个 `pong` 前会话就以 Close/EOF/空闲超时/读错误结束，或握手等响应头超时（`websocket_handshake_timeout`，或整体握手超时落在 WS 阶段）；收到 pong 清零；服务端 `error` 帧 / kicked / resync 是有效应答，不计数。连接拒绝/DNS/TLS 等网络错误与 401/403(带 `{code}`)/429/5xx 不计数、不回退（SSE 也会失败，不能因服务端故障把大量客户端推到 SSE）。**回退到期后重新探测**：SSE 心跳每次成功后检查本连接建立时记下的回退截止时刻，已过期则返回 `Resync`，走「停读 → 排空 → 1s 停顿」重连并重新尝试 WS。读流/空闲检测（WS 与 SSE 同为 75s，任何帧含 pong 都算活动）、心跳、串行业务处理属于同一个可取消生命周期，任务快照失败独立重试，不再阻断建连。握手整体有超时，登出、手动重连及关停会取消旧生命周期。

**同时在线名额**（FluxCloud `maxOnlineDevices`，free=2；`maxDevices` 仅为宽松受信任设备上限 free=10，`maxSyncDevices` 已删除）：任务通道（WS 或 SSE 回退）与同步 SSE 共用同一设备租约，满额时新设备 403 `online_device_limit` → `ErrorReason::OnlineDeviceLimit`，不 halt、不退出登录，`Reconnecting` + 30s 重试；`/sync/items` 只做只读准入（已持租约或此刻可准入），不占租约。`agent.device.disconnect {id}` → `POST /devices/{id}/disconnect` 让另一台下线（云端驱逐租约并 60s 冷却，推 `presence.kicked`，被踢端进入同一等待态）。在线数徽标含本机，`maxOnlineDevices>0` 时显示 `x/N`。**同步冲突**：推送条目带 `baseVersion`（该键最后见到的云端 version，拉取时脏键不抬高）与 `editedAt`（按云端 `Date` 头校正的编辑时间，播种条目不带）；云端检测到他设备在 base 之后改过该键时按 `editedAt` 严格更新者胜，缺 `editedAt` 视为 0 必败，落败条目在响应 `conflicts` 中返回，agent 按拉取值应用并清脏。

账号作用域请求使用 `cloud::RequestEpoch` / `CloudApi::at_epoch` 绑定发起时的会话；获取 token、HTTP 响应及最终状态写入都核验代际，最终写入与事件投影在同一状态锁内完成。退出后重登相同 UID 也属于新代际，不能仅按 UID 判断请求仍有效。旧响应的 `session_changed` 不表示当前会话过期，不得据此退出新账号。

`CloudConnectionDto` / `CloudConnectionChanged` 是仅在内存中的运行态。`connected` 需要通道建立、在线租约确认（WS 为第一个 `pong`，SSE 回退为首次 HTTP 心跳成功）及随后的设备名册刷新成功；名册失败进入 `reconnecting` 并独立重试，不能依赖另一次上线事件才能恢复。**设备名册只在三种时机刷新**：首次在线确认、收到 `presence` / `device.updated` 事件、上一次刷新失败后的重试 tick——心跳（WS 或 SSE 回退）本身不再拉 `GET /devices`。PC/Web 共用此投影，把失去新鲜度的设备在线状态显示为未知。`agent.remote.reconnect` 的 `{accepted:true}` 只代表接受请求，普通 `agent.device.list` 不打断健康连接。

事件业务队列（队列里是纯 JSON payload，SSE 去掉 `data:` 前缀、WS 取文本帧）有条数与单条大小组合上界，满时背压读取，不可丢弃命令后假设快照能恢复（pause/resume 与 deleteFiles 不是可重放状态）。resync 与普通事件按 FIFO 处理；通道关闭（WS Close / SSE EOF）或心跳失败先停止读取并排空已接收事件，再重连，退出或账号失效仍可直接取消。主动背压不算网络空闲，心跳和会话取消仍独立。`session.revoked` / `presence.kicked` 在读取侧立即应用，`presence` / `device.updated` 只触发名册刷新。重新连接 RPC 走本地请求通道，不排在慢云请求之后。

FluxCloud 的 `409 presence_connection_missing`（SSE 回退的 HTTP 心跳）与 WS `{"type":"error","code":"presence_connection_missing"}` 帧等价：按 resync 短暂停后重建通道，不退出登录，也不误报云不可达；WS `{"type":"error","code":"online_device_limit"}` 帧等价心跳 403，映射为 `OnlineDeviceLimit`（30s 固定重试）。成功心跳（HTTP 204 / WS pong）不能凭空创建在线：在线必须持有活跃的 `/tasks/ws`、`/tasks/events` 或 `/sync/events` 连接。FluxCloud 的 presence 和事件 hub 当前限单活进程部署，反代须透传 `Upgrade` / `Connection` 且读超时 > 30s，配置与验证见 FluxCloud `README.md`；客户端无法用本地标记修复服务端分流或代理拦截。

## Headless 服务器（`fluxdown-agent --server` + `fluxdownd`）

入口 `native/agent/src/main.rs` 的 `--server` → `server_mode::run_blocking` → `runtime::run_with(.., Some(ServerRuntime))`。agent 在同目录拉起 `fluxdownd`（`supervisor.rs`，继承环境 + `with_extra_env` 追加 `FLUXDOWN_DEMO_URL`），经 loopback 调 daemon：默认 `127.0.0.1:17801`，被占用 / 被系统保留时 daemon 回退系统分配端口并在数据目录发布 `daemon-endpoint.json`（容器 `--network host` 与宿主机桌面版共存也不冲突），见上方「本机端口与端点发现」。`FLUXDOWN_BIND` 是显式地址：被占用即启动失败（stderr 带地址），不回退，Docker 端口映射保持不变。Gateway listener = `fluxdown_api::server::api_router(AgentApiHost)` + `/rpc` + `server_mode::router`（setup / `/api/web/*` / demo / SPA fallback）。

- **env**（`server_mode.rs::ServerConfig::from_lookup`）：`FLUXDOWN_BIND`（默认 `[::]:17800` 双栈：`runtime.rs::bind_gateway_socket` 对 IPv6 通配地址经 socket2 显式关 `IPV6_V6ONLY`，无 IPv6 时退回 `0.0.0.0` 同端口，占用 / 权限错误不退回；`gateway/restart.rs::TrackedListener` 把 `::ffff:a.b.c.d` 对端还原成 IPv4 再交 `ConnectInfo`；NAS 包 / Docker / OpenWrt 默认同改；允许非回环，不看 `lan_enabled`）、`FLUXDOWN_TOKEN` + `FLUXDOWN_TOKEN_FORCE`（预置访问密钥；FORCE 每次启动覆盖；不过 `validate_access_key` 则忽略并告警）、`FLUXDOWN_WEBROOT`（可选磁盘覆盖）、`FLUXDOWN_LANG`（`/ping.language` 回退）、`FLUXDOWN_DEMO`/`FLUXDOWN_DEMO_URL`、`FLUXDOWN_ALLOW_LOCAL_PLATFORM`（真值为 `1`/`true`/`yes`/`on`；显式把所有已鉴权连接视为本机来源，只额外放行打开 / 定位任务产物，等同允许远程用户触发服务器 OS 打开文件，默认勿开）。daemon 读：`FLUXDOWN_DATA_DIR`（引擎数据根；agent 状态在 `<root>/agent`）、`FLUXDOWN_DATABASE_URL`（`sqlite:`/`postgres://`）、`FLUXDOWN_SAVE_DIR`（仅 `default_save_dir` 未设置时播种）、`FLUXDOWN_DEMO_URL`（`daemon.task.create` / `daemon.group.create` 精确匹配守卫）。**局域网设备互联（L1）由 agent 实现**（`native/agent/src/link.rs` + `link/{service,storage}.rs`，协议本体在独立 crate `native/link` = `fluxdown_link`；引擎只保留 Db 存储后端 `fluxdown_engine::link::DbLinkStorage` 给 Flutter hub / 旧 server）：`FLUXDOWN_MDNS`（假值 = 不 mDNS 广播 / 浏览，配对码 + 手动地址仍可用）、`FLUXDOWN_LINK_NAME`（局域网里显示的设备名；缺省 server 模式 `FluxDown Server`、桌面为设备名）、`FLUXDOWN_LINK_ADVERTISE_ADDR`（覆盖本机自报回连地址，见下一条）**已恢复生效**；新增 `FLUXDOWN_TRUSTED_PROXIES`（逗号分隔反代 IP，仅这些 + 回环对端才采信 `X-Forwarded-For`/`X-Real-IP` 做配对猜码节流分桶）。网关只监听回环（桌面默认 `lanEnabled=false`）时：配对码结果 `addresses` 为空、不广播、不自报回连地址；`--server` / `lanEnabled` 正常。配对地址支持 `host` / `host:port` / `http(s)://host[:port][/base]`（反代 / https / 子路径），非 FluxDown 的 4xx / 重定向 / HTML → `pairingNotFluxDown`，网络失败 → `pairingPeerUnreachable`。数据面端点见下一条，都免 management 开关（`route_group_guard` 白名单）。接单目录回退：非本机风格绝对路径 → daemon 默认目录，带目录建任务失败 → 去掉目录重试。
- **局域网设备互联数据面 v2**（`fluxdown_link`）：请求头 `X-FluxLink-Device/Ts/Nonce/Tag/Enc: v2`，MAC = HMAC-SHA256(link_secret, `fluxlink-v2\n{METHOD}\n{path}\n{ts}\n{nonce}\n{sender_fp}\n{receiver_fp}\n{hex(sha256(密文))}`)，请求 / **响应**体都是 ChaCha20-Poly1305（AAD 绑定方向、方法、路径、收发指纹与请求 nonce）；`/ping` 带 `linkProtocol: 2`，发起方对 `<2` 的对端直接 `PeerOutdated`（不发请求）；v1 / 缺失方案头一律 401（JSON `{reason: notPaired|clockSkew|unauthorized, serverTime}` 仅作诊断，不得据此持久化）。经认证端点 `/api/v1/link/{tasks,info,unpair}`：`info` 双向交换 name / platform / appVersion / addrs≤4 / cloudDeviceId / defaultSaveDir / pathStyle，只在内容变化时写盘与推送；`unpair` 把对端记录标 `revoked`（拒绝其入站、本机不再向它下发，重新配对覆盖并清除）。配对三步（hello / reveal / confirm）请求体上限 16 KiB。`FLUXDOWN_LINK_ADVERTISE_ADDR` 是逗号分隔的 `host[:port]` 或 http(s) URL（缺端口取网关实际端口），用于 Docker / NAS。直连不访问 FluxCloud、不进云设备名册；本机云设备 ID 只经已认证链路告知已配对对端。
- **访问密钥** = `AgentState.gateway_user_token`（热更新 `TokenCell`，兼容 API 与 Web 共用）。策略单一事实源 `server_mode.rs::validate_access_key`（ASCII 可见字符、8–128 位、字母+数字），Web 镜像 `web/src/lib/token-policy.ts`；server 模式下 `agent.gateway.patch.userToken` 不能写空/弱密钥（否则匿名 setup 重新打开）。旧 server 数据目录的 `local_server_token` 与开关由 `link::migrate_legacy_state` 导入，无需手工迁移。全新安装首次运行开启 takeover/jsonrpc/api/mcp 分组。
- **首次设置门禁**（`runtime.rs` 的 `require_token=true` + `api/src/server.rs::route_group_guard`）：访问密钥为空时，`/download`、`/download/batch` 与 `/jsonrpc`（POST/WS 升级）返回 403 `setup required: set the access key first`，即使 aria2 名单方法也不可达；管理 API/MCP 本就拒绝空 token。Web SPA、`/ping` 与 setup 引导接口仍可用，初始化就绪前 setup 可能 503。headless 不自动补桌面暴露面的 token，首次设置前 aria2 与接管不可用。
- **路由**（server 模式专有）：免鉴权 `GET /api/v1/setup/status` → `{setupRequired,minLength}`、`POST /api/v1/setup {token}`（仅密钥为空时，已设 409；daemon 就绪 + 迁移完成前 503）；`/rpc` 浏览器鉴权 = 子协议 `fluxdown.rpc.v1` + `fluxdown.token.<base64url 无 padding>`（Bearer 也接受 agent.token 或访问密钥），带 `Origin` 时其主机须等于 `Host`（或 `X-Forwarded-Host` 首段）的主机否则 403——头里带端口须等于 Origin 有效端口，不带端口只比主机（nginx `Host $host` / NPM 会丢对外非默认端口）；浏览器文件面（Bearer 或 `?token=`）：`POST /api/web/blobs/{torrents,plugins}`（转发 daemon blob，4 MiB）、`GET /api/web/files/tasks/{id}`（流式转发已完成文件）、`GET /api/web/exports/{id}`（daemon 诊断 JSON）、`GET /api/web/logs/export`（日志 zip）；演示模式 `GET|HEAD /demo/file`（64 MiB 确定性流、Range、1 MiB/s）。其余 GET/HEAD → SPA。
- **Web UI 内嵌**：`web-ui` feature 下 `native/agent/build.rs` 递归嵌入 `FLUXDOWN_EMBED_WEBROOT`（缺省 `web/dist`），`web_assets.rs` 托管（强 ETag + 304；HTML no-cache、Rollup 哈希文件名 immutable 一年、其余短缓存；未命中回 `index.html`；无 Range；未嵌入 503 自解释页）。改前端须先 `cd web && bun run build` 再重编 agent。
- **进程语义**：server 模式不启 NMH / 不做自启迁移 / 不注册关联；`agent.platform.openTask` / `revealTask` / `copyTaskFiles` 只对本机来源连接放行（`ServerHandle::local_platform_permitted`：环回 TCP + 转发链每跳环回 + 所有 `Host` / `Origin` / `X-Forwarded-Host` / `Forwarded` authority 为字面 localhost / 环回，或显式 `FLUXDOWN_ALLOW_LOCAL_PLATFORM`），建连时判定一次，放行的连接在 `system.hello` 额外带 `agent.openTaskFiles` 能力（桌面宿主恒带，嵌入式移动宿主不带），Web 据此显示「打开文件 / 打开所在文件夹」；`agent.copyTaskFiles`（「复制文件」：产物以文件写入主机系统剪贴板，`platform/clipboard_files.rs` 经 arboard，进程级常驻实例保住 X11 剪贴板归属）另需 `platform::copies_files_to_clipboard()`——`desktop` 特性 + Linux 有 `WAYLAND_DISPLAY` / `DISPLAY`，headless / NAS 构建与远程连接都不带，GPUI 右键 / 应用菜单与 Web 右键据此只在能生效时出现（浏览器 Clipboard API 写不了文件，远程 Web 以「下载文件」替代）；其余 `agent.platform.*` 返回 Unsupported。同机反代的公网域名不会自动获得该能力。SIGTERM/SIGINT 走 `Lifecycle::request_quit`（先关停 daemon 再退出，二次信号强制退出）；stderr tracing（`RUST_LOG`）。Docker 用 tini 做 PID 1。Windows 发布构建带 `windows_subsystem = "windows"`，`--server` 无控制台输出。
- **空闲静默（NAS 硬盘休眠）**：无活动/排队任务、无做种、无到期 RSS、无客户端主动请求时，daemon/agent 不得周期性读写 save_dir 与 data_dir（不 fsync 的写也会被内核回写唤醒机械盘）。落点：daemon 定时文件跟踪扫描受 `idle_file_scan`（默认关，旧库经标记键 `migration_idle_file_scan_off` 一次性迁移为关）经 `should_run_idle_scan()` 门控，客户端获焦 / 页面可见时经 `daemon.task.rescan` 补扫（GPUI `RescanThrottle` ↔ Web `rescanThrottle.ts`）；做种时长仅随上传增量 / 状态迁移 / 关机顺带落库，兜底 30 分钟；DHT dump 30 分钟；仅因暂停的未完成 BT 任务保活的会话 15 分钟后释放；SQLite 池常驻 1 连接不回收（避免 `-wal/-shm` 反复删建）；CDN 配置下发比对后才写、空闲 peek 不读库、agent 未登录不上报；RSS 无语义变化的拉取不落库（运行态以内存为准，`daemon.rss.listSources` 经 actor 重读库并叠加内存运行态）。Doctor `disk_sleep` 检查列出当前阻碍项（做种、RSS、空闲扫描）。部署建议：`/data` 放 SSD / 缓存池。
- **已完成记录保留的触发点（遵守空闲静默）**：`completed_record_retention_days` > 0 时，超期「已完成」任务记录（不含做种中，且只删记录不删文件）只在 daemon 启动后首次加载、任务完成（`on_task_done`）、`daemon.task.rescan`、设置变更四条被动路径上顺带清理，被动路径 10 分钟去抖；不新增任何定时器，定时文件跟踪扫描（`file_scan.tick`）不触发它。
- **Doctor 动态权限探测**：`agent.diagnostics.run` 经 agent 专用的 `daemon.diagnostics.probe`（`require_local_agent`，慢方法）让 daemon 在下载实际发生的进程里对默认 / 队列 / 启用的 RSS 源 / 分类（agent 经 `extraDirs` 追加）保存目录与 daemon 数据目录做「创建→写入→fsync→读回→重命名→删除」往返（不存在的目录在最近的已存在上级探测，不创建目标；`/Volumes`、`/media` 等挂载容器上被拒归为卷未挂载；结果带 `osError`），并以 20s 时限运行已解析到的 ffmpeg / ffprobe / yt-dlp 版本命令（`components::exec_probe` 区分启动被拒与运行失败）。只由用户触发，不属于周期任务。桌面宿主另报 `nmh_launch`（像浏览器那样拉起已注册入口并经它 `ping` 到 agent：Unix 执行 `fluxdown_nmh.sh`，Windows 经 `<ComSpec> /d /c`，`ComSpec` 取注册表配置值）、`nmh_comspec`（见下条）、`nmh_policy`（Windows Chrome / Edge `NativeMessagingUserLevelHosts` / `Blocklist` / `Allowlist` 与 `DisableCMD`，只报告不绕过）、`nmh_ownership`（Unix 属于其他用户的注册文件）、`elevated_run`（Unix 以 root 运行）、`autostart`、`notifications`；Web 隐藏这些桌面专属检查。实现：`native/daemon/src/doctor_probe.rs`、`native/agent/src/diagnostics.rs`。
- **Windows `ComSpec`**（`native/agent/src/nmh/comspec.rs`）：Chrome / Edge（未都开 `NativeHostsExecutablesLaunchDirectly` 时）执行 `%ComSpec% /d /c <host>`，只读自身进程环境、不回退默认值；值空 / 以分隔符结尾 / 文件不存在时扩展只报 "Failed to start native messaging host."。环境变量修改不会推给已运行的进程（只有处理 `WM_SETTINGCHANGE("Environment")` 的资源管理器重读注册表），所以诊断与浏览器式拉起都读**注册表配置值**（`HKCU\Environment` 覆盖 `HKLM\…\Session Manager\Environment`，`REG_EXPAND_SZ` 按 `ExpandEnvironmentStrings` 规则展开），本进程环境只用来报「已修正但修改前启动的程序仍沿用旧值」（`nmh_comspec_restart`，Warn）。修复 `fix_comspec` 只写 HKCU（坏的用户变量在系统变量可用时删除，否则写用户变量 `%SystemRoot%\system32\cmd.exe`；注册表已正确时只重新广播），随后广播 `WM_SETTINGCHANGE`（`platform::notify_environment_changed`）并按新值重新拉起确认；已在运行的浏览器须由用户完全退出后重开（`chrome://restart` 继承旧环境，不算）。`--server` 拒绝该动作。
- **Doctor 修复与提权契约**（`native/agent/src/{permission.rs,diagnostics/repair.rs}`）：修复只在用户点按钮时发生（`agent.diagnostics.repair`）。**提权只做「释放」**——把被 root / 管理员占住的路径还给当前用户（类 Unix 改回属主：FluxDown 自有目录递归、家目录内只改该目录；家目录外的共享目录不抢属主，只加当前用户的可继承 ACL：Linux `setfacl -P`、macOS `chmod -h +a`、Windows `icacls /grant *SID:(OI)(CI)M /L`）；提权命令一律不跟随符号链接（`chown -h` / `-R -h`，释放脚本遇到符号链接目标直接拒绝）。属于当前用户、只是缺权限位的目录不提权，普通权限 `chmod u+rwx`（NMH 目录同理，只有属主不是自己的目录才请求授权）；真正的重写 / 注册回到普通权限完成，修完重新探测，仍未通过报 `repairIncomplete`。提权外壳：Linux `pkexec`、macOS `osascript … with administrator privileges`、Windows PowerShell `.NET ProcessStartInfo{Verb=runas}`（只有它能把 UAC 取消识别为 1223）；Windows 先以普通权限试 `icacls`，被拒才转 UAC，超时（大目录传播继承项）直接报错不转 UAC。命令是固定模板，路径只作参数（PowerShell 经环境变量传入），目标路径取自重新探测；根目录 / 家目录及其上级 / 系统与软件安装树（Linux `/opt` `/snap` `/nix` `/usr` `/var` …，macOS `/opt` `/nix` `/Library` …）/ 挂载容器本身（`/mnt` `/media` `/srv` `/run/media` `/Volumes`，其中的卷按共享目录处理）拒绝。提权进程不创建任何 FluxDown 文件或注册项；不写 HKLM、不改组织策略与 Defender 配置（只引导用户去系统设置）。`--server` 不提权：`server_mode_denies` 拒绝 `fix_dir_access` / `enable_autostart` / `open_settings` / `test_notification` 与 NMH / 关联动作；`fix_component`（daemon 的 `daemon.diagnostics.fixComponent` 补托管组件执行位）在 headless 仍可用。失败原因 `ErrorReason::{ElevationCancelled, ElevationUnavailable, RunningElevated, RepairIncomplete, RepairNotApplicable}`，GPUI / Web 在 Doctor 页就地展示。
- **兼容 API**：`AgentApiHost`（`native/agent/src/api_host.rs`）转发 daemon RPC 实现 `ApiHost` 全部核心方法（任务/组/RSS/插件/市场/站点凭据/aria2 WS 通知经 `task_events.rs`）；旧 server 独有的扩展 REST（`/api/v1/config`、队列增删改、stats、fs/list、components、webhooks、logs、token/regenerate、`/api/v1/ws`）已**废弃**，管理面只走 `/rpc`。

**分发目标**（`fluxdown-agent` + `fluxdownd` 同目录，入口 `fluxdown-agent --server`，镜像名仍 `ghcr.io/zerx-lab/fluxdown-server`；资产随统一 `vX.Y.Z` release 发布，历史版本在 `server-v*` release）：Docker（amd64+arm64）、群晖 SPK、QNAP QPKG、飞牛 fnOS FPK、OpenWrt IPK / APK + LuCI、Unraid CA 模板、CasaOS。脚本在 `packaging/`、`promotion/`、`docker/`。

**飞牛 fnOS**（`packaging/fnos/`，`build_fpk.sh` 拼装应用目录后交官方 `fnpack build`；CI 钉 fnpack 版本 + sha256）：`platform=x86|arm` 各一包；`run-as package`（用户 `fluxdown`）；`config/resource` 声明 data-share `fluxdown`，`cmd/main` 取 `TRIM_DATA_SHARE_PATHS` 首项作 `FLUXDOWN_SAVE_DIR`，`TRIM_PKGVAR` 作数据目录；入口为端口服务 `type=url` 直开 `:17800`（agent 自带密钥鉴权与 `/rpc` WebSocket，不走 index.cgi / 统一网关）；`FLUXDOWN_INSTALL_SOURCE=fnos` → `UpdateInstallKind::Fnos`（`managedPackage`）。规范：<https://developer.fnnas.com/docs/core-concepts/framework/>。

**OpenWrt**（`packaging/openwrt/build.sh <ipk|apk>`，同一份载荷 / 服务脚本出两种格式，无 OpenWrt SDK / `po2lmo`）：ipk = 24.10 及更早（opkg，纯 tar 手打）；apk = 25.12 起（apk-tools v3 ADB 格式，只能 `apk mkpkg` 生成，CI 在 `alpine:3.24` 容器内打，默认 compat 可被 25.12 自带 apk 3.0.5 安装）。apk 细节对齐 OpenWrt `include/package-pack.mk`：版本 `X.Y.Z-rc.N` → `X.Y.Z_rcN`（apk 不认 semver 预发布，文件名仍用原版本）、`/lib/apk/packages/<包>.{list,conffiles,conffiles_static}`、升级只跑 `post-upgrade`（已启用才重启，不改自启选择）、改过的 `/etc/config/fluxdown` 升级时保留并落 `.apk-new`；包未签名，安装需 `--allow-untrusted`。两种格式都按 aarch64 子架构各出一包（opkg / apk 都拒绝架构不符）。

**OpenWrt LuCI**：运行状态经 ubus `service list` 每 5s 轮询；访问密钥 = UCI `token`（非空时 init 传 `FLUXDOWN_TOKEN` + `FLUXDOWN_TOKEN_FORCE=1`，前端校验镜像 `validate_access_key`），当前生效密钥由 `/usr/libexec/fluxdown/luci-token` 用 `jsonfilter` 只取 `agent-state.json` 的 `gatewayUserToken`（ACL 只放行该脚本，状态文件绝不整体给浏览器）；汉化 = 视图内置 zh 词典（`T()`：`_()` 命中优先，否则按 `L.env.lang` 取词典）。

## 应用内更新（`native/agent/src/update/`，桌面、headless 与原生 Android 共用）

状态归 agent：`UpdateService`（`update/mod.rs`）独占 `UpdateStatusDto`，经 `AgentSnapshot.update` + `AgentEvent::UpdateChanged` 推送（协议 v8）；方法 `agent.update.{check,download,install,cancel}` 都返回 `UpdateStatusDto`。UI 只渲染状态、发请求，GPUI（`crates/settings/src/update_view.rs` 判定 + `about.rs`、`crates/app/src/update_notices.rs` 提醒窗口时机与通知）与 Web（`web/src/lib/update.ts` ↔ 同一套阶段 / 按钮 / 文案键规则，`shell/UpdateStatus.tsx` 横幅与重启遮罩）逐条对齐。

- **桌面新版本提醒窗口**（`WindowKey::UpdatePrompt`，视图 `crates/settings/src/update_prompt.rs`）：独立辅助窗口，不依赖主窗口；按钮「跳过此版本 / 稍后提示 / 立即更新」（只能手动升级时为「前往官网下载」），点立即更新后窗口保留显示下载 / 安装进度。是否弹出只由 `fluxdown_protocol::update_prompt::is_due` 判定（有新版本且阶段为 available / downloading / ready、未跳过、不在稍后提示期内），用户选择存设备本地 agent 偏好 `desktop.update_skipped_version` / `desktop.update_remind_after_ms`（稍后提示 = 24h；关闭按钮等同稍后提示）。界面在运行时 `update_notices` 电平触发开窗并为稍后提示到期设定时器；没有 UI 连接且托盘可见时由 agent `shell::reconcile_update_prompt` 以 `--capture` 拉起界面只开提醒窗口（与确认拉起共享单飞 / 静默期，同一版本最多 3 次）。菜单「检查更新…」有新版本即开窗，不受跳过 / 稍后提示限制；被跳过的版本也不再自动后台下载。
- **宿主**：`UpdateService` 内部区分 agent 宿主（状态进事件总线、本进程替换文件后重启）与委托宿主 `UpdateService::delegated` + `UpdateDelegate`（原生 Android：状态与「已校验安装包就绪」交给 App，App 交给用户默认的 APK 安装程序，安装前被拒 / 放弃经 `install_failed` 回报，交接后停在 installing 由下次启动对账）。两者共用同一状态机、检查、续传下载与 `pending.json` 对账，**禁止在 Kotlin 另写一套**。
- **检查**（`update/release.rs`）：`/api/release?channel=` 按安装形态取桌面顶层资产、`server.assets` 或 `mobile.assets`；更新包 URL 恒为 `/api/download/<资产名>?tag=<tag>`（不带 tag 会拿到「最新稳定版」，与检查结果竞态）。校验和取组件哨兵 `SHA256SUMS-app.txt` / `SHA256SUMS-server.txt` / `SHA256SUMS-mobile.txt`，回退 `SHA256SUMS.txt`；没有该资产的条目 → `manualReason=noAsset`，只给手动下载。**发布流水线改资产命名或哨兵格式必须同步这里与官网 `/api/release`。**
- **官方站点（域名迁移）**：`DEFAULT_API_BASES = [fluxdown.com, fluxdown.zerx.dev]`（主域名优先；2026-10 迁移前的版本是旧域名优先），检查时错峰竞速（上次成功的站点先发，3s 内无结果或已失败才发下一个，首个成功者胜出），胜出站点用于同一轮的更新说明、校验和、更新包与 `releasePageUrl`；可信下载域含 `zerx.dev` / `fluxdown.com` / GitHub。两域任一可用即可更新；已发布客户端仍先试旧域名、失败 3s 后换新域名，旧域下线不影响它们升级。
- **网络出口**（`native/agent/src/egress.rs`）：检查与下载不读也不另存代理设置，每次向 daemon 取 `daemon.egress.plan`（引擎 `egress.rs`，与下载任务同一全局代理）；版本清单 / 更新说明 / 校验和以 `verifiedPayload=false` 只拿代理，更新包以 `true` 允许插件按下载任务同一 resolver 规则改写来源（失败或 SHA-256 不符丢弃 `.part` 后回退官方地址）。daemon 不可达或不认识该方法时退回系统默认网络——自更新是修复 daemon 的途径。原生 Android 仅在本机主机运行时取其 daemon 方案。嗅探规则包（ed25519 签名）走同一出口。
- **自动行为**：偏好 `general.auto_check_update`（默认开）→ 启动 30s 后首检、之后每 6h（按墙钟判定到期、10 分钟轮询一次时间，系统睡眠 / 休眠不会把检查无限推后；只走网络，不碰磁盘，符合空闲静默）；可一键更新时自动后台下载 + 校验（`<agent 数据目录>/updates/<版本>/`，`.part` + Range 续传）→ `ready`。`ready` 后周期检查照常进行，查到更新的版本即取代旧包重新下载（失败 / 同版本保留就绪包），常驻不重启的机器也能跟上后续发布。永不在无用户点击时安装。用户取消某版本的下载后该版本不再自动下载。
- **安装形态**（`update/install/detect.rs`，启动时检测一次）：Windows 安装版 / 便携版（`portable` 标记）、macOS `.app`、Linux AppImage / deb / Arch / 便携 tar.gz、headless 二进制包；资产按**硬件**架构选（x64 Windows 构建跑在 ARM64 上读注册表 `PROCESSOR_ARCHITECTURE` 换 arm64 包，Rosetta 下的 x64 macOS 构建经 `sysctl hw.optional.arm64` 换 arm64 包）。deb / Arch 经 `dpkg -S` / `pacman -Qqo` 取 `/opt/fluxdown` 的**归属包名**：只有官方包名 `fluxdown`（`scripts/package_gpui_linux.sh`）可应用内更新；其它包名（AUR `zerx-lab-fluxdown-bin`、发行版仓库、第三方重打包，以及认不出包名）→ `managedPackage`、不取官方资产（官方包与之冲突，`pacman -U --noconfirm` 必然失败，成功也会顶掉用户的包来源），界面文案 `updateManualSystemPackage`。不能自更新：未注入 `FLUXDOWN_APP_VERSION` 的开发构建（`unofficialBuild`）、`FLUXDOWN_INSTALL_SOURCE=docker|synology|qnap|openwrt|fnos` 或 `/.dockerenv`（`managedPackage`，Dockerfile 与 NAS 启动脚本已设置）、非官方系统包（`managedPackage`）、目录不可写、deb/Arch 无 `pkexec` 或图形会话、macOS App Translocation / 从 DMG 运行、macOS 当前 bundle 无 TeamIdentifier。
- **安装与重启**（`install/` + `restart.rs`）：先写 `updates/pending.json`，在旧进程仍运行时替换文件（失败整体回滚、原程序可用）：便携 / 服务器包解压（拒绝穿越与链接条目，跳过 macOS AppleDouble `._*` / `__MACOSX`），只替换包内存在的文件，旧文件改名为 `*.fluxdown-old`（Windows 允许改名运行中的 exe；`portable_data/` 永不触碰）；AppImage 同目录临时副本 rename 覆盖；deb/Arch 经 `pkexec` 调 apt-get(dpkg) / pacman；macOS 挂载 DMG（或 `/usr/bin/tar` 解 tar.gz）→ `ditto` 到同卷暂存 → `codesign --verify --deep --strict` 且 TeamIdentifier 与当前一致 → `xattr -s -d -r com.apple.quarantine` 清除暂存 bundle 的隔离标记（失败即放弃本次更新）→ 两次 rename 交换 bundle → 刷新新 bundle 修改时间并 `lsregister -f`（失败只告警）。启动时 `install::heal_installed_quarantine` 对「应用程序」文件夹里仍带隔离的已安装 bundle 做同样的清除与登记（从翻译副本运行时无从得知原位，由 `fluxdown_nmh` 冷启动前处理，见上方 `native/nmh`）。随后 `Lifecycle::request_restart` 走完全退出（先停 daemon），**agent 运行期完全结束后** `main` 执行计划：Windows 安装版静默跑安装器（`/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /SP- /LOG=`，`setup.iss` 静默 `[Run]` 带 `--after-update` 拉起桌面）；其他桌面形态分离启动 `fluxdown-desktop --after-update`（macOS `open -n FluxDown.app --args --after-update`，AppImage `$APPIMAGE --after-update`）；headless 在 Unix 上 `exec` 原路径原 argv（PID 不变，systemd / tini / 终端照常），Windows 分离重启。
- **关闭原因**：桌面形态的更新重启仍是 `service-quit`（桌面退出，由计划重新拉起）；headless 为 `service-restart`（`CLOSE_REASON_SERVICE_RESTART`），浏览器保持重连，握手 `serviceVersion` 变化即 `location.reload()`；握手 `protocolIncompatible` 时 60s 内只自动刷新一次（覆盖 Docker / NAS 跨协议升级）。
- **对账**：下次启动 `pending.json` 目标版本 = 当前版本 → 删除 `updates/`；否则 `failed` + `installIncomplete`。改名残留在启动时清理。桌面 `--after-update` 会等待旧实例释放单实例锁（≤30s）而非把激活转发给正在退出的旧进程，就绪后提示「已更新到 vX」。
- **托盘「重启」**（`TrayAction::Restart`，位于「退出」之前，文案键 `trayRestart`）：`update::restart::desktop_relaunch()` 登记非更新计划后 `Lifecycle::request_restart`（完全退出，关闭原因仍 `service-quit`）；agent 运行期结束后分离拉起桌面并带 `--relaunch`（等旧实例释放单实例锁 ≤30s，复用 `--after-update` 的等待，但不弹「已更新」）：macOS `open -n <外层 FluxDown.app> --args --relaunch`，Linux AppImage `$APPIMAGE --relaunch`（运行期挂载点会失效），Windows / Linux 其他形态同级 `fluxdown-desktop --relaunch`；找不到桌面程序时退而用原参数重启 agent 自身，连 agent 路径都取不到则不退出。正在退出（含更新重启）时忽略点击。
- **本地冒烟**：仅调试构建认 `FLUXDOWN_UPDATE_BASE_URL`（覆盖官网地址并跳过可信域校验），配合 `FLUXDOWN_APP_VERSION=<旧版本>` 构建、本地假 `/api/release` + `/api/download` 即可跑通 headless 检查 → 下载 → 替换 → `exec` 重启；另起实例时用 `FLUXDOWN_DAEMON_URL` 换 daemon 端口，避免连到本机正在运行的 daemon。
- **原生 Android**（`native/mobile/src/update.rs` 的 `AppUpdater`，经 `FluxCore::app_updater` 取得，进程内唯一，与主机会话无关——远端模式下更新的也是 App 本身）：资产按 `Build.SUPPORTED_ABIS` 第一个有分包的 ABI 取 `android_{arm64,armv7,x64}`，兜底 `android_universal`（`InstallTarget::android`）；`versionName` 不可解析 → `unofficialBuild`；App 侧判定商店安装 → `managedPackage`、可调试 / 签名证书非官方 → `unofficialBuild`。Rust 不起周期任务，调度归 App（前台 6h 节流 + JobScheduler 每日后台检查，非计量网络才自动下载），安装前 App 再校验 APK 包名 / 签名证书 / versionCode，不符按 `verify` 回报并丢弃该包。Kotlin 判定规则镜像 `update_view.rs`（见 `.omp/knowledge/clients.md`）。
