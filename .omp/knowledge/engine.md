## 状态与数据模型

- **任务状态码**: 0=pending, 1=downloading, 2=paused, 3=completed, 4=error, 5=preparing。
- **文件类型分类**: all/video/audio/document/image/program/archive/other；分类规范由 protocol DTO 与当前客户端分类模型承载，用户可自定义匹配模式与保存目录。
- **时间分组**: today/yesterday/thisWeek/thisMonth/older。
- **任务组**: 多文件下载的纯逻辑聚合壳（N 独立子任务 + `task_groups` 行）；组进度由前端 SUM 聚合；空组自动回收（`gc_empty_groups`）。

### 数据库（`native/engine/src/db.rs`，sqlx `Any` 池）

**双后端**：URL scheme 选后端（`sqlite:`/`postgres:`）；两份 DDL 常量（`SQLITE_SCHEMA`/`POSTGRES_SCHEMA`）处理二进制、字节计数与自增主键的后端差异；运行时 SQL 统一 `$N` 占位符；`add_column_if_missing` 幂等迁移（新库建表即全列，旧桌面库经 ALTER 升级）。SQLite 侧 WAL + `synchronous=NORMAL`（进程崩溃不丢已提交事务，断电可能丢最后几笔）+ 外键 + busy_timeout=5000；批量写入仍要合并成单事务。

**当前表（列以 db.rs 为准，此处仅索引）**：
- `tasks`(id PK, url, file_name, save_dir, status, total/downloaded_bytes, segments, created_at, error_message, proxy_url, queue_id, checksum, ignore_tls_errors, bt_selected_files, bt_custom_name, orig_etag, orig_last_modified, audio_url, file_missing, `range_verified`（配额端点续传验证）, queue_order；迁移列：cookies, referrer, extra_headers, resolver_plugin_id, segments_epoch, completed_at, group_id, resolver_item, rss_source_id（RSS 溯源，空=非 RSS 来源）, `origin_url`（展示用真实来源；`.torrent` 任务的 `url` 是 `torrent-file://local` 哨兵，「复制链接」类 UI **一律**读它并空则回退 `url`）, `auto_route`（`ProxyMode::Auto` 的任务级最终链路或站点规则标签 `rule:direct|system|manual|custom`，wire 标签见 `auto_proxy::route`；空=非 Auto 且未命中规则；客户端先整串匹配 `rule:*` 再做 `:system`/`:manual` 后缀拆分）, `unattended`（无人值守创建标记，`NewTaskSpec::unattended_selection` 置位：RSS / 远程派发 / 系统打开链接或拖入 / 外部接管命中设备本地偏好「免打扰跳过二次选择」`download.silent_skip_selection`；start/resume 读它让 HLS/DASH 画质与插件变体静默取默认、「文件已存在」询问按重命名；BT 不读此列——建任务时已按「全选」写 bt_selected_files））
  - 来源归因迁移列 `src_cdn_bytes` / `src_proxy_bytes` / `src_nic_bytes`（BIGINT）：coordinator 在既有 DB flush 节拍按 `NodePool::source_bytes` 把「多 CDN 钉定节点 / Auto 代理路径 / 多网卡链路」的增量以 `segments_epoch` 守卫累加；源站 = `downloaded_bytes` − 三者之和，P2P 协议由客户端整体归 P2P。任何把 `downloaded_bytes` 复位为 0 的写入同语句清零三列。实时值走 `TaskRuntimeDto.sourceBytes`（含在途），持久值走 `TaskDto.sourceBytes`；客户端详情常规页「来源构成」区块的切片算法 GPUI / Web 逐条镜像（见 AGENTS.md §5）。
  - 命名来源迁移列 `name_inferred`（1 = 引擎推断名，HTTP 完成期可精修）/ `resp_name` / `resp_mime`（实际 GET 响应的命名证据），语义见下方 `naming/`。
  - 「文件已存在」逐任务决定迁移列 `exists_decision`（`''` / `rename` / `overwrite` / `skip`），语义见下方「文件已存在策略」。
  - 多插件冲突待选迁移列 `resolver_choice_pending`（1 = 多个 resolver 同时匹配、首次起跑前还要定案），语义见下方「多插件 resolver 冲突」。
  - 分类目录路由迁移列 `category_route`（`CategoryRoute` JSON，空 = 保存目录即最终目录），语义见下方 `category_route.rs`。
- `task_segments`(复合 PK task_id+segment_index；旧库遗留 id AUTOINCREMENT 不再读)
- `task_groups`(id PK, name, source_url, save_dir, created_at)
- `config`(key PK, value)——**所有设置键**都存这里
- `torrent_files`(task_id PK, file_bytes BLOB)
- `queues`(id PK, name, speed_limit_kbps, upload_limit_kbps, max_concurrent, default_save_dir, position, default_segments, default_user_agent, is_running, schedule_enabled/start/stop, schedule_days 位掩码)
- `ed2k_blocks`(复合 PK task_id+block_index, state, downloaded_bytes, retry_count)
- `ed2k_hashset`(task_id PK, hashes BLOB)
- `task_artifacts`(复合 PK task_id+file_name；追踪 sidecar/产物文件供清理)
- `rss_sources`(id PK, `provider_id`/`provider_config`（订阅 provider 适配器与其不透明配置，旧数据默认 `rss`/空）, url, name, enabled, auto_download, start_paused, queue_id, save_dir, interval_minutes, include/exclude_pattern, use_regex, smart_episode, size_min/max_bytes, send_referer, notify_on_download, max_per_fetch, cookies, user_agent, proxy_url, last_fetch_at, last_success_at, last_error, fail_count, `seeded`（首轮是否已完成）, position)
- `rss_items`(复合 PK source_id+guid, title, link, enclosure_url/length/type（声明的下载目标 MIME）, `resolver_item`（插件二段解析标识，空 = 普通直链）, pub_date, fetched_at, status 0..5, task_id 回链, episode_key, reason 原因码；`fetch_failures` / `retry_after` 持久化种子抓取失败退避；`ON DELETE CASCADE` 于 rss_sources)
- `task_create_batches`(batch_id PK, results JSON, created_at BIGINT)：`daemon.task.createMany` 的幂等记录，与该块任务行**同一事务**写入；同键重放直接返回首次逐条结果；7 天前的记录在后续批量写入事务内顺带清理（无定时任务，符合空闲静默）。
- 已完成记录保留（daemon 键 `completed_record_retention_days`，0–3650，默认 0 = 永不；不进云同步目录）：`DownloadManager::purge_expired_completed_records` 经 `Db::list_expired_completed_task_ids`（`status=3`、`completed_at` 非空且早于截止、排除 `seeding_status ∈ {1,8}`，按完成时间升序分 200 条一块）取 id，再走 `delete_tasks_batch(ids, false)`——**只删记录，永不删文件**。一次性迁移 `migration_completed_at_backfill` 把遗留的「已完成但 `completed_at` 为空」行补写为升级时刻（保留窗口自升级起算，SQLite / PostgreSQL 同一事务）。无定时器（空闲静默）：只在进程启动首次快照后、`on_task_done`、`daemon.task.rescan`、设置变更四处被动触发；任务完成与重扫两条路径 10 分钟去抖，启动与设置变更 `force` 绕过；保留期 0 直接返回。某块有清理失败的任务时本轮立即结束，避免重复选中。

**内置队列**: `main`（主）/`later`（稍后下载），播种于 `Engine::new`，不可删/改名；存量 `queue_id=''` 迁入 `main`。**主队列恒运行**（`model::is_always_running_queue`）：引擎 `stop_queue` / `set_queue_schedule` 对它不生效，daemon `daemon.queue.stop` 与带实际定时的 `daemon.queue.schedule` 返回 InvalidArgument（`field=queueId`；「关闭且无时刻」放行为空操作，兼容旧客户端保存流程）；`Db::seed_builtin_queues` 每次启动把旧版本留下的停止 / 定时主队列收敛为运行中、无定时（只在不符时写一行，暂停任务保持暂停）。各客户端对运行中的主队列不显示「停止」、不显示定时（只给 `mainQueueAlwaysRunningHint`）。删除命名队列后，任务归属、排队位置与持久排序都要同步：`TaskQueueChanged` 只带归属，`QueueOrderChanged` / `QueuePositionsChanged` 只带待排顺序（排序键 `order`，见 `queue_order.rs`），`TasksSnapshot` 才是 `queue_order` 归零后的权威来源。

**任务活动与实时采样**：`task_activity.rs` 拥有源端活动代理，`db.rs` 的活动表/保留标记在 SQLite 与 PostgreSQL 同步维护。状态边沿、完整错误、实际重试、分段拆分及 CDN 语义事件先持久化再广播；高频进度不逐帧入库。worker 把已积压的连续记录（≤`ACTIVITY_BATCH_MAX` 条）经 `Db::append_task_activities` 一个事务落库、整批只裁剪一次（逐条事务 + 逐条 `OFFSET 5万` 裁剪曾在大批量导入时长期占住 SQLite 写锁），仍按入队顺序逐条发 `TaskActivityAdded`。ID 在同一数据库内跨重启单调，任务删除级联清理；保留约束及分页上限以 `db.rs` 常量为准，清理过的历史有逐任务截断标记。所有宿主的 `progress_reporter` 必须使用 `Engine::activity_sink`，否则绕过统一记录；关闭时冲刷有超时并报告真实失败。`transfer_activity.rs` 的 RAII 计数只覆盖真实传输生命周期，采样携带源端单调序号；分段几何、活跃传输、配置上限与 BT peers 是不同事实，不能相互推算。

**任务速度历史**（`speed_history.rs`，表 `task_speed_history` 在两套 schema 同步）：`progress_reporter` 对下载态（status=1）任务按墙钟逐秒累计平滑速度（与界面显示同源），横轴只计下载秒数，暂停 / 排队 / 做种不计入；两帧空窗超过 10s 只补 10s（进程挂起 / 休眠）。点数封顶 240，满额相邻两点合并、桶宽翻倍，存储有界且覆盖全程；峰值、累计秒数与传输字节为精确统计，不受合并影响。下载中的历史常驻内存（挂在 `Db` 上，进度报告器与 daemon 查询共享），每 30s 及离开下载态时落库，daemon 停机时 `Db::flush_speed_history` 冲刷——只在下载期间写库，符合空闲静默。「重新下载」（`restart_task`）经 `Db::reset_task_speed_history` 在同一把锁内清内存与库行，迟到的停止帧不会让旧历史复活；换源 / 尺寸变化导致的进度复位不清历史。任务删除级联清理。

**建任务管线**：`create_task` 与 `create_tasks_batch` 共用「内存准备（thunder 解码 / BT 禁用 / 去重 / checksum / 站点凭据 / UA 并入请求头 / 队列默认 / ED2K / 相对文件名）→ 单事务落库（每队列一次 `MAX(queue_order)` 后内存递增、每行一条全列 INSERT、一次 `IN` 回读）→ 发布」三段，单条与批量语义不能分叉。批量一块只读一次 `dedup_same_url` / 活跃 URL / 站点凭据库，块内重复链接解析为块内首个任务；发布顺序 = 先一条 `EngineEvent::TasksChanged`（wire `DaemonEvent::TasksChanged`），再逐条 webhook `task.created`、解析插件缺失报错、稍后下载探测 / 入队。逐条拒绝（`CreateRejection`：BT 禁用 / thunder 解码失败 / checksum 非法 / 请求头非法）不影响同块其他条目；整块事务失败则整块回滚且不留幂等记录。
**任务 HTTP client**：需要专属 client 的任务（单任务代理 / UA、队列默认 UA、忽略 TLS、Auto 走代理、站点规则出口）经进程级 `client_cache.rs` 按（代理指纹, 生效 UA, ignore_tls）缓存复用（超过 64 个整体清空，指纹不含 `rules`）；构建一次约 70ms，禁止每任务 / 每请求重建。同键任务共享连接池与 cookie jar，与全局 client 语义一致。

## 下载引擎（`native/engine`）

- 平台存储 FFI（`disk_space.rs`、`segment_coordinator.rs`、`bt_sparse.rs`、`bt_downloader.rs`）保留实际分配/并发扩容、大卷宽度和饱和计算语义，不机械替换成 fs2；具体锁定版本差异见 `rule://no-unsafe-in-rust`。空间出参仅成功后读取，fadvise 直接错误码显式记录；Windows 属性读取走安全元数据，错误不能被当作 sparse 标记，测试区分磁盘占用与逻辑长度。

### 6 种协议（分发 = `download_manager::do_start_task`/`do_resume_task` 内单条 if/else 链，每臂 `catch_unwind`）

| 协议 | 判定谓词 | 入口 | 文件 |
|---|---|---|---|
| **HTTP/HTTPS**（默认兜底） | fallthrough | `segment_coordinator`（IDM worker pool） | `downloader.rs` / `segment_coordinator.rs` / `segment_advisor.rs` |
| **FTP** | `is_ftp_url` | `ftp_downloader::run_ftp_download` | `ftp_downloader.rs`（suppaftp 同步 + spawn_blocking） |
| **BitTorrent** | `is_bt_url`（magnet 或 .torrent 哨兵） | librqbit `SharedBtSession` | `bt_downloader.rs` / `tracker_subscription.rs` |
| **HLS** | `hls_downloader::is_hls_url` | `run_hls_download` | `hls_downloader.rs`（M3U8/多码率/AES-128） |
| **DASH / 音视频轨合并** | `is_dash_url` 或有 `audio_url` | `run_dash_download` | `dash_downloader.rs` |
| **ED2K（仅下载）** | `ed2k::link::is_ed2k_url` | `ed2k::run_ed2k_download` | `ed2k/`（mod,link,proto,hash,server,peer,client,server_subscription,upnp,kad/） |

- **HLS 分片调度与测速**（`hls_downloader.rs`，点播视频轨与独立音轨共用）：分片下载完即归还连接许可，数据进 `ReorderWindow` 乱序窗口（领先写盘 ≤ 并发数 × 8 段、缓冲 ≤ 32MiB，队首段永远放行），单一 writer 按序追加到唯一 `.fdownloading` 临时文件——没有分片临时文件、没有合并拷贝，队首慢不再让其余连接空等（旧版许可随写盘释放，8 段成批等最慢一段）。进度 = 落盘字节；测速与宿主流量 = `SegmentMeter` 的 body 接收字节（`ProgressUpdate::transfer_bytes`），限速作用在读取侧而非写盘侧。续传检查点按 `DB_SAVE_INTERVAL_SECS` 节流，暂停 / 出错 / 收尾前补写最新前缀（检查点只会落后：续传截断到检查点、重下其后几段）。直播录制仍按轮询窗口 `buffered` 并发，共用同一计量与读取侧限速。
- **HLS 点播总大小估算**（`hls_downloader/size_estimate.rs`，只服务展示）：总量 = 已知大小分段之和 + 未知分段预测。逐段证据按等级覆盖：BYTERANGE 声明 < 在途响应头 Content-Length（`download_segment_as` 上报）< 已下载待写盘（dispatcher 上报）< 已写盘（writer，含 init 段）；续传前缀按合计字节计入。未知分段：全段带 `EXT-X-BITRATE`（解析进 `HlsSegment::bitrate_kbps`，粘性、BYTERANGE 段不适用）时按标注字节 × 校准比；否则按平均段大小 × 未知段数，仅时长明显混杂（CV ≥ 0.3、≥ 8 样本）才用 `a + b × 时长` 拟合（夹在按段数 / 按时长之间）；变体 `AVERAGE-BANDWIDTH` 作 300s 等效观测加权（有独立音轨先扣音轨实测码率），`BANDWIDTH` 是峰值、只作无证据时初值。不变式：有未落盘段时总量 ≥ 已落盘 + 剩余段数（< 100%），全部落盘时 = 已落盘（100%）。估值随进度帧上报，并在检查点 / 暂停 / 出错时写 `tasks.total_bytes`；收尾前收敛为实际字节、落库并以带文件名的帧越过 manager 500ms 节流；完成帧与 manager 完成落库取实际产物大小，估值不参与完成判定、续传或产物大小。直播总量恒 0。10 条公开点播流回放（8 连接）全程平均误差 2.4%（yt-dlp 7.9%、N_m3u8DL-RE 4.1%），逐流不劣于两者；改参数前用同样方法回放验证。
- **HLS 独立音轨与封装**：master 变体的 AUDIO 组若有 `EXT-X-MEDIA` 独立 URI，`external_audio_uri` 优先选 `DEFAULT=YES` 音轨。开跑前探测可用 ffmpeg；可用时音轨与视频并行下载，各自保留续传检查点，进度汇总两轨字节，收尾经 `mux_video_audio` + `dash_downloader::ffmpeg_copy_to_mp4` 以 `-c copy`（不转码）封装 MP4。音轨下载的真实错误会取消整任务；ffmpeg 不可用时仅下载视频并写 warning 活动，mux 失败则保留视频、尝试另存音轨 sidecar 并写 warning；mux 取消保留两轨临时文件与检查点供恢复。
- **HLS TS→MP4**：`remux_ts_to_mp4` 优先用同一 ffmpeg 流复制入口，不整文件读入内存，也不受内存转换的 192MiB 上限约束；无 ffmpeg 或执行失败才尝试有上限的 `ts2mp4` 内存转换，空间不足 / 转换失败保留 TS，取消不触发内存兜底。`EXT-X-MAP` 的 fMP4 输出不做 TS 转换，只按占名规则改名为 MP4。
- BT 任务绕过 pending 队列，且**不计入** http/ftp 并发计数（`max_concurrent`）。
- **BT 判定只认 `magnet:` 与 `torrent-file://` 哨兵**（`is_bt_url`）。HTTP 的
  `.torrent` **直链不会走 BT**——会被当普通文件下回来一个种子文件。要让直链
  变成真下载，必须先把字节抓下来再以 `NewTaskSpec::torrent_file_bytes` 建任务
  （RSS 订阅就是这么做的，见 `rss/` 的两段式）。
- **DHT 持久化是纯缓存，`SharedBtSession::new` 对它三级兜底**：带 `dht.json`
  起 → 失败则删掉它重试 → 再失败则关 DHT 起（tracker + PEX 仍可用）。起因是
  一份钉着 `addr: 0.0.0.0:58686` 的 `dht.json` 撞上 Windows 动态端口排除区间
  （`netsh interface ipv4 show excludedportrange protocol=udp`；`netstat` 看不到
  占用但 bind 返回 `WSAEACCES` 10013），导致**所有** BT 任务永久 status=4 而
  用户无从自救。**anyhow 错误一律用 `{e:#}` 打印**——`{e}` 只输出最外层
  context，会把这类根因整个吞掉。
- **BT peer 上限 `BT_PEER_LIMIT` = 512**：librqbit 的 `peer_limit` 信号量同时计
  「连接中」与「已连接」，出站拨号从开始就占许可，许可满时入站连接被直接丢弃。
  上游默认 128 在公网 swarm 里会被不可达 peer 的连接尝试占满（#825 实测约 120/128，
  可用 peer 仅 5–10）；连接中数量由 `connect_rate` × 超时另行约束。下调前先实测。
- **uTP（`bt_enable_utp`，默认开）**：开启时监听模式为 `TcpAndUtp`，出站并发拨 TCP + uTP；
  #825 实测在上限 512 基础上稳态再翻倍，代价是 UDP 收发的系统态 CPU 明显更高（上游仍标为
  experimental）。改动经 daemon 重建共享会话生效。librqbit 来自 `zerx-lab/rqbit`（当前 rev 在分支 `fluxdown/peer-policy`：

- **启动序幕与下载器共用一次单 GET 探测（一次性 URL 安全）**：fresh、非 hint、无音轨对、无有界 Range 窗口的 http(s) GET 类任务（非 HLS/DASH，判据 `downloader::single_get_probe_applies`），序幕（`download_manager::probe_start_meta`）用与下载相同的 client / spec 跑 `downloader::resolve_file_info_held_get`：只发**一个**不带 Range 的 plain GET（无 HEAD、无 Range 0-0；含抖动重试与 UA/Referer 自适应，被拒后才重发），名称 / 大小 / Accept-Ranges 取自其响应头，名字由 `ProbedMeta::from_file_info` 派生（仅 Content-Disposition 为权威名，其余 `name_inferred`；text/html 不产出名字）。**响应本身保留**（`PreprobedInfo.held` → `DownloadSpec::with_held_response`，take-once），单流 `download_single_once` 与 coordinator 零进度的 plain 首连接直接消费它而不发新请求；随后按 hint 语义运行（Range 裁决 UNKNOWN，由同一响应的 `Accept-Ranges: bytes` 裁决后再升多段，长度未知则单流读到 EOF）。一次性签名 URL 因此只被真实数据 GET 消耗一次。「文件已存在」询问会丢弃保留的响应（答复后重起会再发一次 GET）；取消 / 跳过 / 失败随 spec 释放。序幕探测失败 / 取消 → `preprobed=None`，下载器按同一判据自己跑单 GET。hint、续传、HLS/DASH/FTP/BT/ed2k、非 GET 仍走原路径；`meta_prober` 仅保留给排队态后台 HEAD 与非 HTTP 协议（HEAD 不消耗一次性令牌，见 `meta_prober::probe_link_kind`）。

### 引擎子系统（一句话职责）
- `download_manager.rs`（~7300 行）：任务生命周期、并发、队列（内置 + 命名，启停/每日定时边沿触发/顺序）、任务组、自动重试、协议分发、off-actor 插件解析插桩、速度平滑（EMA α=0.4，1s 采样窗；`ProgressUpdate::transfer_bytes` 存在时以接收字节测速并随转发帧发宿主本地 `EngineEvent::TaskTransferred`，两种计数切换时重设基线）、WAL checkpoint。
- `download_manager/boost.rs`：**Boost（优先下载）**——单任务独占，其余活跃 / 排队任务让位暂停（`auto_paused_ids` 有序），结束时按序恢复。只接受未结束任务（status 0/1/2/5），已完成 / 失败返回 `BoostError`（daemon 映射 `conflict` + `ErrorReason::TaskStateConflict`，客户端菜单另做前置提示）。优先任务离开在途集合（活跃 / 解析中 / 排队）即结束 Boost：常规路径各自清理，`on_task_done` / `on_resolve_ready` 尾部 `reconcile_priority` 兜底（插件解析失败 / 裂变、「文件已存在」取消等）。状态仅在变化时写 config `boost_state`（引擎私有，UI 不读写）；启动时 `resume_on_start` 读后即删：`auto_resume_on_start` 开且优先任务属被中断任务 → 恢复 Boost（其余被中断任务并入让位登记），否则让位任务按被中断任务处理。
- `downloader.rs`：共享原语（`DownloadError` 含 Ed2k/Ed2kIntegrity/Cancelled、`RequestSpec`、HTTP 探测与下载执行、完成期原子占名）。

- `segment_coordinator.rs`（~8500 行）：IDM 式动态分段（按需分配、按 ECF 挑选预计完成最晚的在传分段并按持有者/帮手速率比例均衡拆分、连接复用、per-domain 连接策略学习——负面上限 + 正面起步提示双观察面、`fallocate` 预分配）。拆分计入帮手的请求建立耗时（`SplitCost`：`send→响应头` EWMA + 逐段速率缺失时的「近期总吞吐/在传段数」估计）：持有者在帮手收到首字节前就能下完的余量不拆，拆分点按 `keep = h·(setup·g+R)/(h+g)` 补偿帮手起步延迟（`path_scheduler::split_keep_with_setup`）。子模块 `segment_coordinator/request_path.rs`：SYS 租约的 Range 请求复用首个 206 学到的**重定向终点**（不再每段重放源站 302），终点任一失败（非 2xx / 传输错误 / 头超时）即本任务永久退回原始 URL，不消耗段重试、不当作服务器拒绝；域名连接缓存仍按原始 URL 记。拒绝降级：首个 403/429 乘性减半额度后，降额前已在途的超额连接被拒只退休 worker（`shedding_excess`），只有额度内仍被拒才升串行 / 写单连接缓存。Auto 默认档扩容到天花板时若增益接近线性（吞吐增幅 ≥ 连接增幅 × 0.8，同 Ghost Downloader 自动提速口径）且剩余字节够喂饱，任务内把天花板翻倍（`in_task_uncap_ceiling`，上限同 `HINT_UNCAP_MAX`，负面 cap / 显式段数不解封）。子模块 `segment_coordinator/multipath.rs`：每 ramp 窗口的连接稳态采样（以租约真实开始时刻/字节建立基线；首个完整窗预热，短初窗累计，按实际时长算速率；限速窗不计，只有完整零增量窗判停滞）→ 路径估计、冷路径探索 worker、完成时间抢占（分段子令牌取消 → `WorkerEvent::Preempted` → 余量回 Pending 立即续派）、Auto 主导链路标签与先验回写。

  - **版本一致性（不发 If-Range）**：续传与分段只发纯 Range（If-Range 会作废一次性签名 URL），版本安全靠 206 的 ETag/Last-Modified 后验。单流续传（`download_single_once`）的 206 validator 与 DB 基线致命不符时，丢弃旧前缀、不带 Range 重发完整请求并回写新 validator（与 416 / 不可信 206 同一出路），不再以 `VersionChanged` 终态失败（旧基线会让之后每次续传撞同一错误）。多段全程没有任何响应带 ETag（CDN 剥离）且最终有多段时，coordinator 完成前由 `segment_coordinator/splice_audit.rs` 向服务器重取文件首/中/尾各 4KiB 与落盘逐字节比较：确凿不符 → `VersionChanged`（Path B 清盘单流重下）；审计请求失败、非对齐 206、压缩、超时等一律视为无结论放行。

- `proxy_rules.rs` + `rule_route.rs`：**站点代理规则**（配置键 `proxy_rules`，JSON 数组，顺序即优先级；用户 2026-10 决定）。`domain`（`,`/`;`/空白分隔，自动含子域，IDN→punycode，IP 精确）或 `regex`（完整网址、不区分大小写、`size_limit` 1 MiB）→ 出口 `direct` / `system`（静态系统代理，不跑 PAC，检测不到直连）/ `manual`（全局手动字段，不全直连）/ `custom`（规则自带 URL）。四种全局模式下都生效；**任务设置优先**：只有 `proxy_url == ""` 的任务（及未自带代理的 RSS 订阅）看规则。只认 http/https/ftp/ftps，环回永不匹配。规则只挂在 `from_config_map` 产出的全局 `ProxyConfig.rules`（单槽编译缓存），`resolve()` 与一切派生出口恒为 `None`。任务级：`task_http_context` 返回 `TaskEgress`（链接命中 → 标签 `rule:*`、关 PAC / Auto 上下文；规则 client 构建失败时 router base 置空，让每个命中请求在 `client_for` 处报错，**不得**静默回退任务出口）；逐请求：`RequestSpec.egress`（`EgressRouter`）在 `http_request::send` 每跳换 client（命中他条规则才换，未命中沿用任务出口）；**插件解析过的任务以源链接（页面 URL）定任务出口**，解析产物视同重定向由 `rule_route::apply` 在 PAC 之前用最终链接重匹配（命中他条规则才改道，未命中沿用源链接出口——`youtube.com` 规则也管 googlevideo 下载）。Auto 故障转移跳过 `rule:*` 任务。插件请求的规则匹配见下方 `plugin/call_egress.rs` 条；宿主自身下载经 `egress::RoutedClients`。严格校验 `validate`（daemon `patch_config` 写入前拒绝、`daemon.config.proxyRoute` 草稿检查）与 `explain`（「测试网址」）也在这里，客户端不在本地匹配。只改规则走 `DownloadManager::set_proxy_rules`，不清 route_health / 连接上限。BT / eD2K 节点连接与 Webhook 不受规则影响。
- `pac.rs` + `pac_js.rs` + `pac_route.rs`：系统 PAC。脚本经 `egress::client_builder` 直连异步取回（http/https/file，2 MiB 上限，不含 `FindProxyForURL` 的响应视为劫持页拒收；成功 5min / 失败 30s、WPAD 失败 5min 缓存）。`pac_js`（仅 `plugins` feature，QuickJS，每次新建 Runtime、64 MiB / 3s 预算含脚本内有界 DNS）执行 `FindProxyForURL[Ex]`，按 Chromium 约定传 URL（https 只传 `scheme://host[:port]/`），结论按 (PAC, URL) 缓存 60s；无 JS 引擎或执行失败退化为端点提取（`evaluated=false`）。`pac_route::apply` 在 `run_http_family_task` 起跑时（resolver 补丁之后、任何请求之前，可被取消打断）按 `PacRouting` 修正出口：**System** 仅在无静态系统代理且脚本真正执行时按链接选出口（走代理时关多 CDN、多网卡），经 PAC 选中的代理以传输失败告终时 5 分钟内排到列表最后（Chromium 语义），否则保持历史行为；**Auto** 用本链接的 PAC 结论改写系统代理路径（直连 → 去掉，代理 → 改指该端点，缺席 → 补为备选，与手动代理同端点去重），单路径备用链路不改。任务等脚本最多 3s，WPAD 从不阻塞任务。任务级代理、None / Manual 模式不参与。
- `egress.rs`：**宿主自身外网请求的唯一出口**（受管组件、插件市场包、tracker / server.met / nodes.dat 订阅；agent 的自更新与嗅探规则包经 `daemon.egress.plan` 取同一方案）。客户端一律经 `Egress::routed` / `RoutedClients::new`（= 下载任务同一装配，跟随全局代理与站点规则：`new` 立即构建全局 client 保持坏代理快速失败，每个请求前 `client(url)` 按命中规则惰性取规则出口 client；`Egress` 每次读最新配置，调用方必须传含 `rules` 的全局配置而非 `resolve()` 后的）；`Egress::plan` 经 `proxy_endpoint_for` 按源 URL 匹配一次规则。内容有独立来源哈希 / 签名的载荷经 `Egress::route_verified` 按下载任务同一 resolver URL 规则交给插件改写（如 GitHub 加速，多插件命中按无人值守规则定案、不弹框），只接受单一 https 直链，改写地址失败或内容不符回退原地址。校验和、索引、版本清单等完整性锚只走代理、不交给插件。下载任务的拦截器阶段不作用于宿主自身下载。
- `plugin/call_egress.rs` + `plugin/bridge.rs`：**插件调用出口**。每次插件调用（任务解析、新建下载预解析、`route_with_plugins`、插件订阅、登录）带一个 `CallEgress`（`HostContext.egress` → `BridgeHttpRequest` / `YtdlpSpec` 的 serde-skip 字段，脚本不可见）。逐请求：命中站点规则（`flux.fetch` 按请求 URL、yt-dlp 按首个位置参数）→ 规则出口；否则调用的 fallback。fallback 由 `plan_call` 按**源链接**定（同 `task_http_context` 口径）：任务 / 订阅自带代理（不看规则）> 源链接命中的规则 > 全局模式（System 现场检测）> Auto 计划（已排程备用链路或 `pick_auto_takeoff` 起飞，其余未试、未阻断的代理按先验降序、直连最后）。无调用级出口（常驻宿主、通知钩子、元数据探测 / 失败阶段拦截器）按全局规则 + 全局模式现场解析。dev 插件同样遵循规则与代理，私网 / 本地域恒直连。yt-dlp：显式出口恒注入 `--proxy`（直连注入空值），全局 None 与 Auto 直连路径不注入（插件自带 `--proxy` 仍可用）。**Auto 换路**（`PluginManager::run_planned`）：一步失败且 `NetObserver` 证实走 fallback 的请求断在传输层（fetch 经 `net_failure::classify` 并在错误文案追加 `[net:*]`；yt-dlp 看 `ERROR:` 行特征或超时；或墙钟超时时 fallback 请求仍未完成）、整机网络可达 → `record_path_failure(源链接 host)` 并换下一步重跑；判据不读插件抛出的文案。超时时仍在等网络不计入熔断。**解析与下载同出口**：任务解析在 actor 上制定计划（`resolve_egress_plan`），worker 同一占位 / 世代 / 取消令牌内重跑（选择框只在成功后出现，不重复询问）；回流 `absorb_resolve_egress` 把断过的路径并入 `auto_failover_attempts`，成功时记 `ResolvedEgress`，起跑 `take_start_route` 一次性消费：以源链接定出口，Auto 下以 `ForcedRoute` 单路径钉在解析所用路径（无备选、不竞速、PAC 不改写；标签复用 `direct` / `proxy:cached:*` / `proxy:failover:*` / `direct:failover`），并禁用多网卡聚合。下载失败换路排出的目标在下一次恢复时成为解析计划首步。拦截器经 `intercept::sync_egress`（起跑、规则改道 / PAC 之后、探测竞速接管时）跟随任务当前出口。
- `auto_proxy.rs` + `path_scheduler.rs` + `cdn/node_pool.rs`：`ProxyMode::Auto` 是**多路径调度**，没有「采样→一次性热切换」状态机。直连（SYS + 多 CDN 钉定节点）、手动代理、系统代理（同端点去重）都是同一 `NodePool` 的路径；探索即真实分段下载（字节写入文件、零丢弃）。租借规则（`path_scheduler` 纯判据）：冷路径只在 ≥1MiB 的工作上分 1 条探索连接（coordinator 额外放出至多 1 个探索 worker）；失败只降排序不降速率估计（连续 3 次才踢）；单连接估计低于最优一半的路径出竞争集；竞争集内按 cap 分散、按 score 择优；开放式首段/plain GET 只留起飞路径。在途连接按完成时间判据（剩余/本连接速率 > 2×剩余/最优实证速率 + 1s；不设剩余字节下限——建连开销已在交接侧计入，下限会让极慢连接握住拆分最小片以下的尾部碎片拖尾；最优基准只认本任务窗口样本或完成租约，不认先验）在当前字节处抢占交接，整窗零字节即判停滞。代理路径错误归因路径本身（含 Range 失效/错位，翻译为 `CdnNodeFailed` 回收重派），validator 不一致（`VersionChanged` 或 206 路径的 `Other("validator mismatch")`）立即踢除该路径并记 NoSwitch；SYS 上的传输层失败在仍有其它路径存活时同样回收重派（每任务 8 次配额，耗尽后按原语义上抛）；交接窗口抑制 ramp 评估/收缩，用过备选路径的任务不学习域名连接上限/起步提示。跨任务先验 `route_health.rs`：每 (host, 路径) 的单连接速率对数折扣均值（半衰 12h，config `auto_route_health` v3，网络指纹（出口 LAN IP）epoch——换网整表丢弃、**离线=unknown 不清表**；系统代理端点另成 epoch，见下条），只用于起飞排序（代理先验须领先直连 1.5× 才以代理起飞，近期走不通的路径不起飞）与备选路径初值，实测首窗即覆盖。云端只提供 CDN hints 排序先验，不参与路由决策、不新增遥测。failover **独立于通用重试配额**：手动代理、系统代理、本地直连在一个自动恢复周期内各尝试至多一次（先验更快的代理优先，近期走不通的跳过），三路均失败后只服从通用重试，杜绝 ping-pong。主导链路（窗口累计字节最多的路径）落 `tasks.auto_route` + `EngineEvent::TaskRouteChanged`（wire 标签不变：`direct[:sampled|:pinned|:failover]` / `proxy:{sampled,cached,failover}:{manual,system}`）。代理设置变更同点清 `route_health` + `domain_conn_caps` + failover 状态。
- Auto 换路的判据与学习（`net_failure.rs` + `auto_probe.rs` + `route_health.rs`）：
  - **传输失败只按类型分类**：`net_failure::classify` 读 `io::ErrorKind`、reqwest `is_timeout`/`is_connect`、Windows SChannel HRESULT 与依赖库固定英文前缀，结果以 `[net:<code>]` 标签追加进 HTTP 任务错误文案；`is_route_transport_error` / `is_retriable_error` 有标签即以标签为准（`tls` 不同路径重试），无标签（FTP/HLS/DASH、旧库存量）才回退关键词。reqwest 0.12 的 Display 不含根因、中文 Windows 的 OS 描述是本地化文本，关键词必漏。
  - **探测阶段竞速**（RFC 8305 式）：Auto 有备选路径的 GET 类任务，序幕单 GET 探测与下载器自探测都经 `auto_probe::race_probe`——起飞路径一轮断在传输层立即放出全部备选；拿到 HTTP 应答则撤销错峰、不竞速；否则错峰到点放出（有先验 2s / 无先验 1s / 已阻断 0）。第一条成功路径胜出并就地接管 `DownloadParams`（client、`proxy_config`、`AutoProxyCtx`、改走代理时关多 CDN）与路由标签（起飞失败 → `*:failover`，只是慢 → `*:sampled`）。
  - **路径失败权重**：传输失败记 `record_path_failure`（1h 半衰、封顶 4），`path_blocked` 的路径不选作起飞（`pick_auto_takeoff`）、不作 failover 目标、竞速错峰为 0；任一成功实测清零。来源：探测竞速（胜出时含起飞路径）、manager 任务级失败（按标签归因路径）、coordinator 踢除 Auto 路径 / SYS 改道（每任务每路由一次）。
  - **网络指纹只含出口 LAN IP**；系统代理端点单独 `sys` epoch，换成另一已知端点只作废 system 路径，关闭系统代理不清表（格式 v3）。
  - **单路径也学习**：一次性备用链路带无备选的 `AutoProxyCtx`（不竞速、不多路径），coordinator 照常回写先验；单流下载 ≥4MiB 且 ≥2s、未开限速时按任务速率回写起飞路径先验。
  - 限速下不再整体关闭多路径：只有限速器本窗确有节流等待且本任务吞吐 ≥0.5×限速才视为 app-limited（不采样、不改道）。Auto 多路径中 SYS 租约的**传输层失败**只重试 2 次即交节点池改道，HTTP 类瞬时错误仍按 5 次。
- `multi_nic.rs`（config `multi_nic_enabled`，默认关，仅桌面 target 编译 `if-addrs`）：多网卡聚合下载。manager 只折算任务级输入（走代理/Auto 多路径 → `blocked_by_proxy`）；coordinator 起飞后后台 `prepare_links`（解析目标 → UDP connect 探主链路 → 枚举网卡 → 纯判据 `plan_links`），首个完整 ramp 窗口经 `NodePool::add_links` 挂入 `RoutePath::Link(ifindex)` 冷槽位，首连接不等待。规划拒绝：fake-IP（198.18/15，TUN 代理）、局域网/CGNAT 目标、主链路是隧道/点对点（防绕开 VPN）；额外链路排除隧道/虚拟网卡、与已选链路同子网或同 /64（同一路由器 = 同一上游）、目标不具备的地址族、5 分钟内被踢过的网卡（进程内记忆，键含本地地址）。出口绑定：Linux/macOS `interface`（SO_BINDTODEVICE/IP_BOUND_IF），Windows `local_address`（强主机模型，单地址族），链路 client 的 DNS 只返回该链路地址族。调度：链路之间按独立容量注水（容量 = 单连接估计 × 上窗连接数，新租约给「容量/(在途+1)」最高者，≥5% 总容量的空闲链路保底 1 条），不走竞争集；链路最后一条连接只在停滞时抢占；链路路径不写 `route_health` 先验、计入 `alternates_used`（不学域名连接上限）。事件：`TaskCdnEvent` kind `links`/`links_off`（原因码 `multi_nic::off_reason`），节点标签 `NIC:<网卡名>`；单节点池无 sink 时事件暂存，由 `Multipath::poll_links` 每窗转发。生产宿主为 daemon；GPUI（`crates/settings` 下载页「连接与性能」，`SettingsRow::explain` 点击「?」出说明对话框）提供开关。
- `disk_space.rs`：跨平台余量查询（HLS remux/DASH mux ENOSPC 预检）；Unix 原始块数与块大小经 `Into<u64>` 无损扩展后饱和相乘，兼容不同 ABI 的字段宽度，避免同类型强转触发 Clippy。
- `proc.rs`：`no_console_window` —— **每个 console 子进程 spawn 都必须包裹**（ffmpeg/ffprobe/yt-dlp/tar/探版），防 Windows 闪窗。
- `data_dir.rs`：数据目录解析（Windows 便携 `<exe>/portable_data` via `portable` 标记 vs 安装 `%LOCALAPPDATA%`；Linux XDG；macOS App Support；Android files dir）+ 旧版迁移。已有数据迁移不随旧客户端工程退役删除。
- `logger.rs`：全局文件日志宏 `log_info!`/`log_error!`（`#[macro_export]`，`$crate` 前缀跨 crate 安全；每文件顶显式 `use`）。
- `model.rs`/`events.rs`/`selection.rs`：领域类型 / `EngineEvent`（`#[non_exhaustive]`）+ `EventSink` / `HostSelection`。
- `site_auth.rs`：站点 HTTP Basic 凭据存于设备本地 config `site_auth_credentials`。`site_key` 仅支持 HTTP/HTTPS，键为 `scheme://host[:port]`（host 小写、默认端口省略），HTTP 与 HTTPS 隔离；`parse_store` 读取旧 `host` / `host:port` 键时补 `https://`，同站点新旧键并存以新键优先。`download_manager::apply_site_auth` 把凭据注入任务 `extra_headers`，显式用户名/密码优先；无显式凭据且已有 Authorization 时不覆盖。
- `webhook.rs`：`WebhookDispatcher::emit` 同步筛选端点并入队，网络 IO 在端点 worker，失败不影响下载状态。每端点一个有界 FIFO（待投递上限 256），保留事件按 `emit` 入队顺序串行发送；满队列丢最旧待投递项并累计丢弃数，worker 优先写汇总失败投递记录（0 次尝试），不是每条事件派生一个等待任务。全局出站并发 4；dispatcher 释放时关闭队列、唤醒 worker 退出。端点表 `webhook.endpoints` 宽松解析：整份不是 JSON 数组才保留旧表，非对象元素逐项跳过，字段类型不符回退默认值（`lenient` 模块；GPUI `parse_endpoints` / Web `parseEndpoint` 同规则）。`task.created` / `task.started` 早于探测，`download_manager::webhook_task_event` 对空 `file_name` 用 `webhook_provisional_file_name`（http(s)/ftp 路径末段、磁力 `dn=`）补临时名，不带 query。
- `rss/`（`model`/`parser`/`filter`/`mod`）：订阅自动下载。`RssManager` 挂在 `DownloadManager.rss` 上；宿主只提供 60s 节拍（`tick_rss_sources()`）与回流 drain（`on_rss_event()`），抓取 off-actor，建任务仍收敛到 `create_task`。`subscription::SubscriptionProvider` 是 RSS 与插件订阅共用的 provider 分支：内置 `rss` provider 保持原流程；插件在 manifest 的 `subscriptions` 声明 `providerId` + `entry`，由 `PluginManager` 动态路由到 `globalThis.subscribe(ctx)`，返回规范化 `ParsedFeed`，并可通过 `flux.fetch` 请求平台接口。provider 不负责调度、退避、去重、过滤、落库或建任务。三层去重：guid → 单轮上限（超额留 `New` 下轮从旧到新续派）→ 智能剧集去重（识别失败即放行）。

  **两层失败退避不能混为一谈**：订阅 feed 抓取按 `effective_interval_secs` 使用「配置间隔 × `2^fail_count`」，封顶 6h 但绝不短于配置间隔，成功清零，**不自动停用订阅**。条目的种子抓取失败由 `record_torrent_failure` 保持 `New` 并写 `torrent_fetch_failed`，退避为 `600s × 2^(fetch_failures-1)`、封顶 24h；`rss_items.fetch_failures` / `retry_after` 落库，重启不丢退避。`db::rss_dispatchable_items` 仅选到期条目，未失败条目优先，避免失效种子长期占住 `max_per_fetch`；建任务成功或用户手动下载清零条目退避，手动下载不受其限制。

  **enclosure MIME 参与种子识别**：`parser::extract_enclosure` / `map_entry` 保存下载目标声明的 `enclosure_type`（RSS enclosure / media:content、Atom enclosure link；没有 enclosure 时取回退链接的 type），去参数、去空白并转小写。`application/x-bittorrent` 即使 URL 没有扩展名也走「先抓种子字节 → 建 BT 任务」，不只看 URL 形态；magnet 不走种子抓取，二段 resolver 条目的计划不沿用 enclosure MIME。

  `filter.rs` 是纯函数单测主战场，**Web TS 有一份逐条对齐的镜像**（`web/src/pages/rss/filter.ts`）供规则预览用——改任一侧必须同步两处。

  **「无人值守」是 RSS 的核心不变式**——订阅可能半夜抓到 5 集，任何需要用户点一下才能继续的东西都是 bug：① BT 条目建任务时 `NewTaskSpec.unattended_selection=true`，**启动前**落库全选与 `tasks.unattended=1`（HLS/变体选择也静默），否则条目已标「已下载」却仍在等选择；② 引擎内部创建任务也必须通过宿主发布完整任务事实，不能只推缺少队列等字段的进度；③ 手动「重新下载」对**任何**状态（含已下载）都放行。

  **删除任务不触发自动重下**：单删/批删在同一事务清空 RSS 条目的任务回链，将原 `Downloaded` 改为 `Ignored`（已读），其余处置状态保留；不能退回 `New`，否则下一轮自动抓取会重新派发。提交后仅向受影响订阅广播条目快照及源计数，手动下载仍对任何状态开放。

### 受管组件子系统（`components/`，`components` feature）
外部二进制 **ffmpeg + yt-dlp** 的按需安装器/解析器（**不打包**，合规边界——用户在设置「组件」页触发下载）。解析优先级 `manual`（config path）→ `managed`（`<data_dir>/bin/`）→ `system` PATH，wire 为 `ComponentSource{Manual,Managed,System,None}`。ffmpeg = BtbN 静态归档（取单文件，macOS 不支持受管）；yt-dlp = 单平台二进制（全平台）。版本列表经官方镜像 `fluxdown.com/api/components`（旧版客户端用旧域名 `fluxdown.zerx.dev`，两域同源）+ GitHub 兜底。**被两处消费**：插件 `flux.ffmpeg`/`flux.ytdlp` 能力面 + 设置「组件」UI。

## 插件系统（`native/engine/src/plugin`，`plugins` feature）

**可选、可失败的下载任务中间层**，JS 编写（rquickjs 沙箱），声明式设置项（双端自动生成表单）。两个正交能力平面 + 门控工具面：

- **订阅平面**：manifest `subscriptions:[{providerId,entry,timeoutMs}]` 声明 provider，脚本导出 `globalThis.subscribe(ctx)`，通过 `flux.fetch` 自主完成平台请求/解析，返回 `{title,link,items:[{guid,title,link,enclosureUrl,resolverItem,enclosureLength,pubDate}]}`（`providerId` 不得占用内置 `rss`；单条非法跳过并记日志，全部非法才算失败；`ctx.providerConfig` 空值归一为 `{}`）；宿主自动把它挂到公共订阅调度，插件安装/启停后由动态路由读取最新快照。
- **Resolver 平面**：`resolve(url,ctx)→{url}|{manifest}|null`。协议判定**之前**惰性执行、**off-actor**（防冻结 actor），命中后 fail-closed（失败进 status=4，绝不把 HTML 当视频存）。惰性 = 每次 start/resume 重跑，天然防直链过期。支持两段式：初段返 manifest 清单 → 引擎裂变为任务组；二段（`ctx.resolverItem`）返直链。`multi:true` 触发新建对话框前置预解析（`begin_resolve_preview` 只读）。预算按 manifest `resolvers[0]`：`timeoutMs`（默认 10 s，30 s 硬顶）、`memoryLimitMb`（默认 64 MiB，`manager.rs::RESOLVE_MEMORY_CEILING` = 512 MiB 硬顶），见 `manager.rs::resolve_budget_for`；auth / subscription / 拦截器预算不读这两个字段。
- **通知平面**：onStart/onDone/onError/onMetaProbed，全 fire-and-forget（失败仅记日志/超时/`try_acquire`，绝不影响任务状态）；仅 onError 内可 `flux.task.requestRetry`。
- **门控工具面**（manifest `permissions` 声明才注入）：
  - `flux.auth`（`permissions:["auth"]`）：宿主持久化插件认证档案；`save/get/remove` 管理
    Cookie、Bearer、Basic 或自定义 Header。站点键**含 scheme**（`{scheme}://host[:port]`，
    `auth::site_key`）——同 host 的 http/https 是两个不同站点，https 登录态绝不隐式复用到
    http 请求（H-3，防明文 MITM 窃取）；裸 host 输入默认按 https 规范化，插件要登记明确
    允许明文的站点必须自己传 `"http://host"`。`flux.fetch` 按显式 `authRef`（空串视同未传，
    M-5）或插件+站点默认引用自动注入（仅对声明 `auth` 权限的插件推导默认引用），认证档案
    绑定插件和目标站点，过期时隐式引用跳过注入、显式 `authRef` 返回 `authentication_required`。
    档案按 `plugin.<identity>.auth.<site>` 独立配置键保存；旧版整表键 `plugin_auth_profiles`
    仅作迁移兼容，解析失败时记日志丢弃而非 fail-closed 卡死 save/remove/purge（M-1）。
    `flux.fetch` 返回的同名多值响应头以换行符（`\n`）拼接。auth 平面独立信号量
    （容量 2）+独立预算（`auth.timeoutMs` 可选，默认 30s，30s 硬顶），不与 resolve 共享、
    不计入 resolve 熔断（M-2）。凭据清理只挂用户主动 `uninstall`，安装失败的回滚
    `purge`（含其内部 `plugin.<id>.` 前缀清理）不删凭据（M-4）。
  - 登录入口（manifest `auth.entry`）：宿主 RPC `daemon.plugin.auth` 以
    `begin`/`poll`/`cancel`/`logout`/`status` 调用 `globalThis.authenticate(ctx)`；插件返回二维码挑战，
    成功后用 `flux.auth.save` 提交凭据。`logout` 在插件被禁用时也放行——不跑插件 JS，
    直接走宿主兜底删除凭据（M-3）；`poll` 回包省略 `challenge`/`challengeType` 时客户端
    保留上一帧。
  - `flux.ffmpeg`/`flux.ffprobe`（`permissions:["ffmpeg"]`）：近乎全量 argv，**封网 + 封越牢路径**（拒 URL scheme/绝对路径/`..`），牢笼 = 产物目录（仅 onDone 类有产物钩子可用），sema=2，300s/1800s 超时。
  - `flux.ytdlp`（`permissions:["ytdlp"]`）：允许网络抓站，但参数走 `bridge::ytdlp_option_kind` **白名单**，不是危险开关黑名单。只接受列出的完整长选项（带值选项可用 `--name=value`）和独立短选项，拒绝长选项缩写、合并 / 紧贴值的短选项、未知开关及参数数量不匹配；位置参数仅允许 HTTP/HTTPS URL。路径型参数（含 `-o` / `-P` 的类型前缀与 `--print-to-file` 的目标文件）必须是牢笼内相对路径，拒绝绝对路径、盘符、`..`、家目录 / 环境变量展开；`--js-runtimes` 只收裸运行时名，不收可执行路径。执行 / 配置 / 插件加载、浏览器 / netrc 凭据、任意下载器 / 后处理参数等能力不在允许表内。宿主注入 `--ignore-config`、可信 `--ffmpeg-location`（插件不能覆盖）和牢笼内 `--cache-dir`；resolve + 全 hook 可用。
  - `flux.fs`：per-plugin 通用临时文件读写（扁平安全名 + 单文件 8MB/总量 64MB/文件数 100 上限 + unix 0600），取代"每种输入给工具加类型化字段"的反模式。

**插件工作区**：`bridge::plugin_workspace` 统一生成 `<data_dir>/plugins-work/<encoded_id>/`，供 `flux.fs`、`flux.ytdlp` 的牢笼 / cwd 及卸载清理共用（yt-dlp 可另选牢笼内安全 subdir）。identity 按字节作无碰撞编码：`[A-Za-z0-9-]` 原样保留，其余字节一律写成 `_XX`（两位小写十六进制），包括 `_` → `_5f`、`@` → `_40`、`.` → `_2e`；不能用「特殊字符统一替换成下划线」的有碰撞目录名。

**manifest v2（`main` / `contributes`）**：`main = {entry: *.js, events ⊆ VALID_EVENTS, background}`（`background:true` 需 `background` 权限）是 daemon 常驻宿主入口；`contributes = {views ≤16, commands ≤32, sniffRules?, pageScripts ≤16, archive?}`（空数组等同未声明）。view `{id ^[a-z][a-z0-9-]{0,31}$, title 1–40 字符, location activity|settings|taskDetail|window|auth（settings ≤1；auth ≤1 且要求顶层声明 `auth`，承载登录弹窗，旧宿主因未知 location 拒载故作者需设 `minAppVersion`）, desktop?: {entry *.js|*.mjs, networkHosts ≤64, width/height [240,4096] 仅 window}, icon?: 包内 *.svg（加载期读入，≤16 KiB、UTF-8、SVG 文档，经 `PluginViewDeclDto.icon_svg` 下发，客户端按单色蒙版着色）}`；无 `desktop` 的 view 与全部 command 要求有 `main`；带 `desktop` 要求 `desktop` 权限；`sniffRules` 为 `*.json` 且要求 `browserRules`，加载时校验 ≤256 KiB、`format=="fluxdown-sniff-pack"`、≤500 条。`desktop.entry` 只由 GPUI gpui-shell 执行，**引擎从不编译它**，加载时只核对存在。权限全集见 `VALID_PERMISSIONS`（`ffmpeg|ytdlp|auth|tasks|browserRules|desktop|background|intercept|pageScripts|archive`）；风险 `PluginManifest::risk()`：含 `desktop` 或 `pageScripts` = full，含其余任一 = elevated，否则 standard。跨实现夹具 `plugin/fixtures/manifest_cases.json` 由 Rust `manifest_fixture_cases`、SDK `packages/plugin-sdk/src/manifest.ts` 共用；索引仓准入用已发布 SDK 的 `dist/manifest.mjs`（见下文「官方索引发布」）。下发：`PluginDto.{contributions, risk, network_hosts, consent_pending, consent_pending_hosts, package_dir}`。

`contributes.archiveRules` 可与 `archive` JS 共存或单独使用：声明 `{entry: package-relative .json, publicKey: 64 位 Ed25519 hex, updateUrl?: public HTTPS}` 并需 `archive` 权限；签名种子随安装校验，规则包签名覆盖原始 UTF-8 payload 字节。规则限定文件名 glob、扩展名、来源元数据与完成文件头 4 KiB 前缀匹配，不运行远程代码。`flux.archiveRules.status()/update()` 仅 resident main 可读取 / 刷新当前插件状态。
**插件分类与建目录**：`contributes.archive` 指向包内 JS 文件，需 `archive` 权限（elevated）。默认目录跟随授权通过 `CategoryRouteDto` 传递，即使没有配置分类目录也保留空规则路由；显式目录不授权。隔离入口接收 `ArchiveContext{fileName,metadata?,isGroup}`；新结果 `{directories:[...]}` 相对已授权默认根目录创建多级目录，不要求既有分类命中，旧 `{folderName}` 仍仅追加在命中的分类目录下。宿主校验单段安全性、深度与总长度，并逐级检查目录边界；插件不能改根目录、文件名或任意任务。来源解析器的 `archiveMetadata` 提供平台、作者、系列、合集身份与展示名（无凭据、URL、路径），保存在 `tasks.category_route` JSON；仅有元数据而 `base_dir` 为空不构成移动授权。任务组只在根调用，保留成员 `rel_path`，二段解析不覆盖组根事实；BT/eD2K 不接管。分类规则、布局及编辑器由插件维护，宿主不引入通用规则引擎或独立整理设置。实现见 `plugin/runtime.rs::ArchiveResult`、`plugin/interceptors.rs::archive_directories`、`category_route.rs::{archive_group_root,route_before_start,relocate_completed}`；SDK `src/types/flux.d.ts` 与官网 callback 文档同步。

签名 `archiveRules` 包更新仍经统一 egress 与公网 DNS 守卫，启用时持续进行 24 小时一次的公网 HTTPS 检查；手动刷新可立即检查。最近检查时间与错误仅保存在内存中；仅提升新规则包时持久化规则内容及单调序号水位。坏签名、回滚或网络失败保留最后有效规则。它使用原有 `fluxdown-archive-rules` 格式，与分类插件自己的布局 JSON 不同，不能混称同一订阅。切换规则不重分类历史文件；旧签名规则返回单层目录，仍按 legacy 分类子目录语义处理。用户指定目录优先。
加载新插件快照时先清除旧规则匹配缓存，再按当前声明重新验签；声明重载失败不得继续匹配旧包。

**授权与审计（`plugin/{consent,audit}.rs`）**：授权存配置键 `plugin.<id>.consent = {permissions, networkHosts, version, grantedAt, source: user|migration}`；`requested − consent` 非空即 `DisabledReason::ConsentRequired`（不写 enabled 键，授权后直接生效），`set_enabled(true)` 被拒；`daemon.plugin.consent` 只接受与当前 requested 完全相等的集合。首次 `load_all` 一次性迁移（`plugin.consent_migrated`）把已装插件现有能力记为 `migration` 授权。审计表 `plugin_audit`（SQLite + PG，90 天 / 20000 条修剪），`AuditLog` 后台批量落盘（2 s / 100 条，无事件不写盘）；`AuditingBridge` 记 fetch（去 query / userinfo）/ auth / fs 写删 / ffmpeg / ffprobe / ytdlp / task.retry / task.artifact，`PluginManager` 记生命周期，宿主记 `tasks.*` / `settings.update`，桌面脚本经 `daemon.plugin.audit.record`（origin 强制 desktop、action 须 `desktop.` 前缀）。插件嗅探规则聚合在 `plugin/sniff_pack.rs`（`daemon.plugin.sniffRules`，id 改写 `plugin.<identity>.<id>`、tier `plugin`，sequence 只增不减并持久化在 `plugin.sniff_rules.{sequence,hash}`）。

**插件状态广播（单一出口）**：`PluginManager::publish_state` 在专用锁内取 `list()` 并发 `EngineEvent::PluginsChanged`（daemon 映射为 `DaemonEvent::PluginsChanged`），锁保证事件顺序 = 状态顺序、旧快照不会盖过新快照。凡改变 `PluginDto` 可见字段或插件相关查询的操作都在结束时调用：启停、授权、设置（UI 与插件 `flux.settings.update`）、安装 / 升级（含失败回滚，包修订号递增之后）、dev 安装 / 重载（含失败）、卸载、撤回、熔断（先于 `PluginAutoDisabled`）、站点默认写入 / 删除。daemon RPC handler 不再自己发布（仅 `initialize_dynamic_projection` 保留首发）；客户端收到即整体替换插件列表并重拉站点默认。新增插件状态写入点必须调用 `publish_state`。`finish_install` 在加载新代码前按新包版本写好启停状态（失败连同目录一起恢复安装前的 enabled / disabled_reason / revoked_version），不存在「新代码 + 旧熔断 / 撤回状态」的中间态；熔断计数在同版本、同包修订、持续启用时跨 `load_all` 沿用。页面脚本 / 嗅探规则缓存按包修订号失效，卸载即清。

**off-actor 惰性 resolve 接线**：`create_task` 经 `plugin_bind_resolver` 绑定 → 落 `tasks.resolver_plugin_id`（仅存 ID）+ 跳过 meta_prober。绑定规则：显式 `NewTaskSpec.resolver_plugin_id`（任务组成员来自 `CreateGroupRequest.resolverPluginId` = 预解析 `ResolvePreviewResponse.pluginId`）一律落库，不可用时成员以「解析插件不可用」status 4 建出、插件恢复后手动继续即可；无显式 ID 的组成员按预解析同规则 `match_multi_resolver`；其余（含 RSS 二段条目）走 `route_resolver`。`do_start/resume_task` 体首守卫：resolver 非空且未解析 → 占位 active_tasks + off-actor spawn → return；**二段解析任务（`resolver_item` 非空）绑定为空时按建任务规则重绑，仍无插件即 fail-closed，绝不下载原始分享页**，`daemon.plugin.ignoreRetry` 对其拒绝（客户端对任务组成员不提供该菜单）。worker 经 `resolve_rx` 回流，actor `select!` 分支 `on_resolve_ready`（复查生命周期 → 用解析后 url 重算五路协议分派）。**宿主 actor 必须接线 `resolve_rx` + `plugin_retry_rx`**。

**多插件 resolver 冲突**（`plugin/routing.rs`）：多个已启用插件的 resolver 同时匹配时，建任务绑首个候选（identity 升序）并置 `tasks.resolver_choice_pending=1`（二段解析任务不置）；worker 在首次 resolve 前 `choose_task_resolver` 定案并 `set_task_resolver` 改绑清 0；**当前无任何候选时不写回**，待选保持、本次 fail-closed，插件重新启用后下次起跑再定案。从未起跑（无落盘进度、`resolver_item` 为空）的任务若绑定插件被禁用 / 待授权 / 熔断 / 不再匹配而其它插件命中（`bound_resolver_superseded`），起跑前同样走本定案改绑；有进度的任务维持绑定并 fail-closed（中途换 resolver 可能写坏文件）；空绑定从不自动改绑（与「忽略插件重试」结果无法区分）。优先级：用户确认过且覆盖当前全部候选的站点默认插件 > 无人值守（`tasks.unattended`）回退（站点记录插件 > 已绑回退 > 首个候选，并写未确认 `automatic` 记录）> `HostSelection::select_resolver_plugin` 询问（`SelectionKind::Plugin`，60s 超时取回退，可勾「记住」写确认记录；关闭 = 以 `UserCancelled` 取消任务、保持待选）。同站点选择框经每站点锁串行，记住后排队任务直接沿用。站点键 = 主机名小写去 `www.`；候选出现记录外的新插件即重新询问。卸载插件：先后两次清绑定（purge 重载前后，闭合窗口内新建的绑定），待选任务不清绑定（起跑时在剩余候选里重选），站点记录移出该插件、选中它或剩余 <2 的记录删除。RPC `daemon.plugin.siteDefaults` / `daemon.plugin.setSiteDefault`（只能确认 / 改选记录里的候选或删除）。

**config 命名空间**：`plugin.<identity>.enabled`/`.disabled_reason`（`CircuitBreaker` / `Revoked`）/`.revoked_version`/`.setting.<key>`/`.kv.<key>`；`plugin.dev.<identity>`（devMode 路径）；`plugin.site_default.<site>`（多插件冲突的站点记录 JSON `{identity, candidates, automatic}`）；`market.<index_id>.sequence`。identity 格式 `^[a-z0-9_-]+@[a-z0-9_-]+$`。
